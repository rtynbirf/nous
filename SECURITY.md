# SECURITY — политика безопасности НОУС

## Сообщение об уязвимости

Используй **приватное** сообщение о безопасности GitHub:
`Security → Report a vulnerability` в этом репо. Не открывай публичный issue для
уязвимостей и не вкладывай в файлы/логи/тикеты действующие токены, ключи или иные
секреты. Ожидаемый срок первого ответа: 72 часа.

## Модель угроз (по урокам 2024–2026)

| Инцидент-прецедент | Урок | Контрмера в НОУС |
|---|---|---|
| xz-utils (2024) | payload живёт вне git, в тарболлах | артефакты только из CI; ревью бинарных fixtures |
| tj-actions (2025) | теги actions переподвинули задним числом | пины actions по полному SHA; `manifests/pins.yaml` |
| Shai-Hulud 1/2 (2025) | кража долгоживущих токенов, lifecycle-скрипты | `release` отделён, OIDC-короткие токены, секретов нет |

## Правила для субъектов (агентов и людей)

1. Секреты не хранятся в репо; локальные секреты — только в `.envrc` (в `.gitignore`).
2. Деструктивные операции — только с явным подтверждением владельца
   (`manifests/safe-defaults.yaml`).
3. Пин новой зависимости — до первого использования (`scripts/pin_action.sh`).
4. Заметил вставленный воркфлоу, которого нет в `manifests/pins.yaml` и в ADR — тикет
   `security`, не исполняй его.

## Инцидент-протокол

1. Заморозить ветку исполнения (владелец).
2. Ротация всех задетых токенов (владелец, вне репо).
3. Пост-разбор как ADR: как контур пропустил, какое правило добавляем.
