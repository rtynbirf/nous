# src/forge — целевая инстанциация НОУС (форж ISO)

Здесь рождается код форжа — исполнение ТЗ ([docs/spec/tz-nous-forge.md](../../docs/spec/tz-nous-forge.md))
по фазам дорожной карты и тикетам `tasks/open/`.

## Текущее состояние (фаза R0 завершена)

| Каталог | Модуль | Статус | Тикет |
|---|---|---|---|
| `probe/` | обследование хоста | спека готова, ждёт R2 | 0002 |
| `win/` | Windows-ветка ISO | спека готова, ждёт R3 | 0003 |
| `linux/` | Linux-ветка ISO | спека готова, ждёт R4 | 0004 |

Пока каталоги содержат только README-заглушки: код пишут субъекты по тикетам,
а не «по вдохновению». Отклонение от спеки — сначала ADR, потом код.

## Правила каталога

1. Каждый модуль: спека → тесты-фикстуры → код → верификация (см. 05).
2. Пины — только из `manifests/pins.yaml`; хардкод URL/версий запрещён.
3. Общие части (probe, verify) — общие модули, не копипаста между ветками.
4. Windows-ветка исполняется на Windows-хосте владельца; CI гоняет статические
   тесты. Linux-ветка — симметрично.
