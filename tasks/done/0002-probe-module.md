# Тикет 0002 — Probe: обследование хоста

Фаза: R2 (roadmap) · Создан: 2026-10-29 · Предусловия: 0001

## Роль

forge-builder-win + forge-builder-linux — совместная реализация общего модуля
(контракты обоих сборщиков дают право на `src/forge/probe/**`); приёмка — forge-verifier.

## Цель

Модуль `src/forge/probe/` (единый интерфейс `probe run --output <dir>`):
наличие OS/загрузки (BIOS|UEFI), CPU/RAM/дисков, доступности пиновых источников,
каталога вывода, инструментов. Выход: `probe.json` (схема из спеки) + `probe.log`
(сырые команды). Модуль строго read-only.

## Границы

Разрешено: `src/forge/probe/**`, `tests/test_forge_probe*`. Запрещено: workflows,
manifests, чужие модули, любые записи вне temp-каталога.

## Критерии приёмки

- [ ] Тесты на фикстурах зелёные в CI (ubuntu-latest), реальное железо не трогается
- [ ] Схема probe.json валидна; отсутствующие домены → `unknown`, не ошибка
- [ ] Тест подтверждает: ни одной записи вне temp (контроль по пути)
- [ ] `verify.sh` зелёный; сырые выводы в отчёте

## ПОЧЕМУ ТОЛЬКО ТАК

Карта территории обязательна до вмешательства: сборка по устаревшей/отсутствующей
карте — источник класса дефектов «собрал не туда», необратимых в опасных средах.
