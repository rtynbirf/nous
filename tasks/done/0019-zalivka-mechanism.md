## Развёрнутый механизм

`polymath-os`, каталог `scripts/push-bat/` (слито PR #21, main = 0392c39):

- `zalivka.bat` — режимы `sync` / `patch` / `fixcrlf` / `push` / `force`;
  токен только у владельца (Git Credential Manager), транспорт без токена —
  патчи в `<репо>\_patches\` (format-patch + worktree diff);
- `fixcrlf`/`push` прогоняют `git add --renormalize` до коммита — фантомные
  CRLF-диффы физически не попадают в историю;
- `force` только через `--force-with-lease`; журнал `_zalivka_log.txt`;
- `.gitattributes`: `*.bat/*.cmd/*.ps1 → eol=crlf` (cmd чувствителен к EOL
  в метках goto; блобы в репо остаются LF по канону);
- `PUSH.md`: раздел-указатель на механизм.

## ПОЧЕМУ ТОЛЬКО ТАК

Доктрина владельца (PUSH.md, ADR-0002 Tier 1): креды живут на машине
владельца, агентская среда — без токенов. Но ручной путь из PUSH.md не
закрывает три реальные формы расхождения (отставание, незапушенные
коммиты, несохранённая работа) и не лечит фантомные CRLF-диффы, которые на
Windows-клонах маскируются под тысячи изменений. Батник оборачивает те же
git-команды в один прогон с безопасными дефолтами; патчи — транспорт
работы, не требующий кредов вовсе. НОУС — журнал операции, потому что
генеалогия решения (аксиома СИНГУЛЯРНОСТЬ) должна пережить смену исполнителя.
