# Тикет 0003 — Windows-ветка форжа

Фаза: R3 (roadmap) · Создан: 2026-10-29 · Предусловия: 0001, 0002

## Роль

forge-builder-win (реализация), forge-architect (ADR при отклонениях от спеки).

## Цель

Модуль `src/forge/win/`: получение образа по пинам (Fido, SHA256 сверен),
рендер `autounattend.xml` с безопасными дефолтами (WillWipeDisk=false),
сборка ISO oscdimg `-bootdata` (BIOS+UEFI), SHA256SUMS, лог сырых команд.
В CI — статические тесты; реальная сборка — отдельный тикет владельца на Windows-хосте.

## Границы

Разрешено: `src/forge/win/**`, `tests/test_forge_win*`. Запрещено: носители хоста,
непинованные URL, хардкод версий, чужие модули.

## Критерии приёмки

- [ ] Рендер autounattend из фикстур probe → инвариант wipe=false (тест-гейт)
- [ ] Аргументная строка oscdimg сверяется с эталоном (тест)
- [ ] Фикстурный артефакт проходит SHA256-протокол (тест)
- [ ] `verify.sh` зелёный; отчёт с сырыми выводами; что не проверено — явно

## ПОЧЕМУ ТОЛЬКО ТАК

Windows-ветка — первая цель ТЗ; порядок «пины → probe → сборка» гарантирует,
что каждый шаг имеет проверяемое основание, а деструктив исключён дефолтами.
