# Тикет 0001 — Калибровка: источники и пины форжа

Фаза: R1 (roadmap) · Создан: 2026-10-29 · Предусловия: нет

## Роль

forge-architect — исполнитель калибровки (контракт даёт право на секцию `forge:` пинов);
forge-librarian — state-снимок после приёмки. Приёмка — forge-verifier.

## Цель

Каждый ресурс секции `forge:` в `manifests/pins.yaml` имеет статус `calibrated`:
официальный источник, версию/SHA256, метод и дату проверки. Ресурсы:
windows-image (официальный канал Microsoft), fido (pbatard/Fido: релиз + SHA256
скрипта), debian-netinst (Debian 12, вариант с firmware), опционально ubuntu-lts.

## Границы

Разрешено: `manifests/pins.yaml` (секция `forge:`), `docs/spec/implementation/01-sources.md`
(уточнения методов проверки), `state/` (снимок). Запрещено: код, workflows, тесты.

## Критерии приёмки

- [ ] Нет записей `pending-calibration`; у каждой записи `sha256` + `verified_at` + `method`
- [ ] Каждый официальный SHA сверён с сайтом источника (сырой вывод в отчёте)
- [ ] `verify.sh` зелёный; тест структуры по-прежнему проходит
- [ ] Снимок `state/` после калибровки

## ПОЧЕМУ ТОЛЬКО ТАК

Калибровка предшествует любой загрузке: без пинов конвейер качает непроверенное —
нарушение аксиомы карта=территория на первом же шаге.

## Изменения (2026-10-29, forge-architect, по правке протокола)

Частично исполнено паком генезиса v0.2: URL официальных каналов, методы и даты
выставлены (статусы `calibrated-url`); SHA256 и fingerprint ключей остались
`null` по протоколу TOFU — иначе в реестр попали бы выдуманные хеши
(нарушение аксиомы 2; обоснование в `docs/genesis/revision-0.md` §4-I2 и
`docs/decisions/0006-manifests-pins.md`).
