# Тикет 0014 — SINGULARIS: CI-валидация контрактов субъектов

Фаза: SINGULARIS-1 (roadmap-singularis) · Создан: 2026-10-29 · Предусловия: частично независимо (схемы готовы)

## Роль

forge-verifier (гейт) + forge-librarian (машиночитаемые слои контрактов).

## Цель

Сделать существующие контракты `.claude/agents/*.md` enforceable уже до полного runtime:

1. Для каждого из 5 контрактов — параллельный машиночитаемый слой
   `.claude/agents/<роль>.contract.yaml`, валидируемый `schemas/subject-contract.schema.json`.
2. Тест-гейт: каждый contract.yaml валиден по схеме; scope.allow/deny непусты и согласованы
   с md-контрактом (человекочитаемое не расходится с машинным).
3. CI (ci.yml) гоняет этот тест — расхождение контракта = красный main.
4. Пока валидатор — python + jsonschema (уже в requirements-dev? проверить; иначе
   минимальный свой checker по required-полям — без новых зависимостей).

## Границы

Разрешено: `.claude/agents/**`, `tests/**`, `.github/workflows/ci.yml` (только job тестов),
`schemas/**`, CHANGELOG. Запрещено: release.yml, `manifests/**` без ADR, права контрактов
расширять (только формализация существующих).

## Критерии приёмки

- [ ] 5 contract.yaml валидны по схеме; тест гейта зелёный
- [ ] Намеренная порча contract.yaml (в тесте) → красный гейт
- [ ] md и yaml не расходятся (тест сравнения ключевых полей)
- [ ] verify.sh зелёный; новых внешних зависимостей нет или они запинены

## ПОЧЕМУ ТОЛЬКО ТАК

A4 требует прав в конфиге, а не в надежде; сейчас права есть только в md-прозе — машина их
не проверяет. Схемы уже приняты (ADR-0013) — невалидированные схемы это карта без
территории. Минимализм: не ждать runtime (0010), enforce поэтапно.
