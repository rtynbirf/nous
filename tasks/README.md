# tasks/ — очередь воли НОУС

Воля владельца оформляется тикетами-файлами. Один тикет = один субъект = одна цель.
Протокол исполнения: `docs/guides/execution-branch.md` и спека
[07-agent-dispatch](../docs/spec/implementation/07-agent-dispatch.md).

## Каталоги

- `open/` — задачи к исполнению, нумерация сквозная `NNNN-<slug>.md`.
- `done/` — исполненные, принимаются только по вердикту верификатора
  (переносит хронист, ссылка на PR обязательна).

## Обязательные секции тикета

1. **Роль** — исполнитель из реестра (`.claude/agents/`).
2. **Цель** — измеримый результат (файлы, команды, зелёный verify).
3. **Границы** — пути, разрешённые к изменению.
4. **Критерии приёмки** — чек-лист доказательств.
5. **ПОЧЕМУ ТОЛЬКО ТАК** — обоснование задачи и её порядка.
6. **Предусловия** — какие тикеты/фазы должны быть закрыты.

## Инварианты

- Тикет без вердикта верификатора не переносится в `done/`.
- Параллельность — непересекающимися границами; пересечение границ = конфликт,
  решается владельцем.
- Изменение цели тикета после старта — новая строка «Изменения» в тикете
  с датой, а не тихая правка.
