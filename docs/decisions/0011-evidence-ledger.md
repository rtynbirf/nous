# ADR-0011: Журнал доказательств с цепочкой хешей

Статус: принято · Дата: 2026-10-29 · Субъект:nous-genesis

## Контекст

Аксиома 2 (КАРТА = ТЕРРИТОРИЯ принудительно) требует, чтобы каждое утверждение о
прогоне имело проверяемую запись. До сих пор доказательства жили в текстах аудит-доков
(`docs/genesis/audit-2026-10-29.md`, CHANGELOG) — карта без механики: человек может
проверить только прочитав всё. Разбор архива «Public Repo Synthesis» показал рабочий
аппарат коллег: append-only журнал, где каждая строка содержит `seq, prev, ts, hash`,
а `hash = sha256(канонический JSON строки без hash)`. Правка любой старой строки ломает
все последующие хеши.

## Решение

1. НОУС ведёт журнал доказательств в формате `evidence.jsonl` (по строке на запись,
   JSON), совместимым с форматом коллег: `seq, prev, ts, hash` + поля записи
   (`claim, status, method, detail, limitations, checked_at`).
2. Механика — `src/lib/ledger.sh` (bash, без зависимостей кроме coreutils):
   `ledger_append <файл> '<claim>' <status> '<method>' '<detail>'` и
   `ledger_verify <файл>` (exit 0 — цепь целостна).
3. Статусная лестница: `GAP < UNKNOWN < PARTIAL < CONFIRMED` (+ `FAILED`,
   `NOT_APPLICABLE`). Правило конституции: ни один скрипт НОУСа не ставит CONFIRMED
   иначе как по факту первоисточника (TOFU-сверка, живой прогон) — PARTIAL всегда
   требует заполненного `method`.
4. Журнал пишется в рабочую директорию прогона (`NOUS_TARGET_DIR`/`state/`), а не в
   дерево репо: репо хранит конституцию и код, территория хранит факты. Инцидентные
   записи копируются в audit-доки ссылками, не дублированием.
5. Защищённость: цепочка ловит небрежную правку и удаление, но не злоумышленника с
   доступом ко всему файлу (он пересчитает цепь). Внешний якорь НОУСа — git-история
   самого репо (коммиты с артефактами прогонов); подпись cosign/Sigstore — осознанно
   отложено (см. «Отложено»).

## ПОЧЕМУ ТОЛЬКО ТАК / ПО ДРУГОМУ НЕТ

- **Почему bash-реализация, а не python-модуль коллег.** Весь контур форжа НОУСа —
  bash (`src/lib/*`, `src/forge/linux/*`); журнал вызывается из `build.sh`/`scan.sh`
  в фазах, где python-зависимость уже есть (pins), но вводить новое требование
  рантайма ради 40 строк — нарушение самодостаточности (аксиома 3). Формат строк
  идентичен — взаимная проверяемость с инструментом коллег сохраняется.
- **Почему не в git-историю, а в jsonl-файл.** git-история доказывает состояние кода,
  но не факты прогонов (какой SHA собрался, чей ключ сверен); jsonl-журнал —
  машинно-верифицируемая карта прогона, которую можно приложить к тикету.
- **Почему не подпись сразу.** Подпись без инфраструктуры ключей — карго-культ:
  подписывать нечем и не кому. Цепочка закрывает 90% инцидентов (небрежная правка)
  при 10% затрат; осознанный остаток риска задокументирован.

## Отложено

- Внешняя подпись журнала (cosign/Sigstore/Rekor) — когда появится выпускной контур
  релизов НОУСа (тикет 0007/R6).
- Репликация журнала в git (ежепрогонный коммит state/) — после первого реального
  использования сканера субъектом forge-verifier.

## Последствия

- Каждый скрипт НОУСа с побочными эффектами обязан писать в журнал (probe, forge,
  scan) — гейт на инвариант в тестах.
- Формат `evidence.jsonl` становится контрактом: изменения — только через новый ADR.
- `ledger_verify` входит в верификатор прогона: цепь сломана → прогон FAILED.
