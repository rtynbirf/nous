# ADR-0007: ветка `agents/execution` как земля исполнения

Статус: принято · Дата: 2026-10-29 · Решает: владелец

## Контекст

Агенты должны исполнять то, что предписано в репо (ТЗ, roadmap, тикеты), но
конституция (`main`) должна оставаться инвариантной в процессе исполнения.
Нужен порядок работы агентов с git-историей.

## Решение

Двухконтурная схема: `main` — конституция (меняется только осознанным merge
владельца после верификации); `agents/execution` — земля исполнения (агенты
работают PR из веток задач `agents/<роль>/<NNNN>-<slug>`). Тикеты из
`tasks/open/` — единственный источник работ. Вердикт верификатора — условие
закрытия тикета.

## ПОЧЕМУ ТОЛЬКО ТАК

- Инвариант конституции: исполнение не может ослабить правила, по которым
  оно проверяется. По-другому нет: агенты, работающие прямо в main, меняют
  и судью, и подсудимого одним коммитом.
- История решений: PR-поток в ветке исполнения = журнал «кто, что и почему»;
  прямой push этот журнал стёр бы.
- Изоляция ошибок: дефектная задача живёт в ветке, конституция не краснеет;
  CI на `agents/**` гоняет те же проверки — дрейф ловится рано.

## ПО ДРУГОМУ НЕТ

- Работа агентов прямо в main: неконтролируемая деградация конституции;
  ревью задним числом не восстанавливает инвариант.
- Репо на задачу: дробит тело организма; межзадачная согласованность
  становится межреповым протоколом.
- Одна общая ветка без роли-скоупа: пересечение границ субъектов в истории.

## Последствия

- Техническая защита веток (rulesets) — шаг R6: сейчас защита дисциплинарная
  (контракты, CODEOWNERS), позже — техническая.
- Периодический merge `agents/execution → main` — акт владельца; хронист
  ведёт заметку о накопленных, не слитых изменениях.
