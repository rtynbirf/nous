# ADR-0016: мембрана выпуска — релиз сверяется с телом и с прошлым собой

Статус: принято (мандат владельца, чат 2026-11-10; тикет 0023) ·
Дата: 2026-11-10 · Решает: владелец

## Контекст

ADR-0015 дал релизу точный аттестуемый набор, но у релиза осталось три
дыры, подтверждённые живыми событиями 2026-11-10:

1. **Квотная рана аккаунта.** Три прогона release упали на шаге
   выкладки артефактов: `Artifact storage quota has been hit` — пул
   хранения Actions (артефакты + пакеты GHCR) был забит девятью
   версиями Docker-образа `combain-v2`. CI уже защищён (TH-RTP-06:
   docs-артефакт `continue-on-error`), а релизный гейт остался строгим —
   и это правильно: лечится корень (санация GHCR), а не ослаблением гейта.
   Но сам релиз НИЧЕГО не проверял вокруг себя: собрал — выложил — ушёл.
2. **Изданный релиз никем не сверяется.** SHA256SUMS.txt подписан
   аттестатом, но никто никогда не пересчитывал хэши ассетов
   опубликованного релиза. convincing ≠ verifiable (A10): аттестат
   без живой перепроверки — убедительность, а не проверяемость.
3. **Состав организма может молча дрейфовать.** SBOM строится, но
   никто не сравнивает SBOM нового релиза с SBOM предыдущего: файлы
   могут появляться и исчезать между версиями без следа в тикетах.

Мировая практика 2025–2026 (волна-3 разведки, веб-поиск 2026-11-10):
SLSA v1.2 прямо называет build provenance рекомендованным способом
удовлетворения требований SLSA (slsa.dev/spec/v1.2/build-provenance);
GitHub artifact attestations дают unfalsifiable provenance
(docs.github.com/actions/concepts/security/artifact-attestations);
OpenSSF Scorecard проверяет и миграции зависимостей, и защиту релизов
(scorecard.dev). Ниша, которой нет ни у кого: **непрерывная сверка
релиза с собственным прошлым как гейт в CI**, а не постфактум-аудит.

## Решение

1. `scripts/release_membrane.py` (stdlib-only) — три команды:
   - `self-check`: свежесобранный набор — точный состав (4 файла),
     формат SHA256SUMS (hex64 + два пробела + имя), каждый хэш
     пересчитан с диска, суммы не хэшируют сами себя;
   - `gate`: скачивает ассеты последнего изданного релиза, пересчитывает
     хэши против ЕГО SHA256SUMS.txt, строит SBOM-drift (CycloneDX
     компоненты: добавленные/удалённые) между изданным и свежим SBOM.
     Дрейф краснит релиз, если в `state/sbom-ack.json` нет акка,
     привязанного к sha256 изданного SHA256SUMS.txt, с тикетом и
     причиной. Отдельные коды отказа: 2 (состав/аргументы),
     3 (локальные хэши/формат), 4 (состав прошлого релиза),
     5 (хэши прошлого релиза), 6 (дрейф без акка) — не врать о причине
     (A2);
   - `sbom-diff`: чистый дифф двух CycloneDX-файлов, отчёт.
2. `release.yml`: `self-check` и `gate` встают между SHA256SUMS и
   аттестацией (сначала сверили себя и прошлое, потом аттестовали);
   по тегу `v*` релиз дособирается до GitHub Release с точным набором
   ассетов — тег теперь сам превращается в изданный релиз (раньше
   издание было ручным действием среды и могло не случиться).
3. `tests/test_release_membrane.py`: тест-крест с
   `test_release_sbom.py` (два реестра точного набора не могут
   разойтись), формат сумм, самопроверка на живом наборе в tmp,
   дрейф-сценарии с подменой сети (красный без акка, зелёный с акком,
   first-run без релизов).

## ПОЧЕМУ ТОЛЬКО ТАК

- **Сверка с прошлым, а не только с собой.** Релиз, который проверяет
  только то, что собрал сам, ловит опечатки, но не ловит дрейф. Мембрана
  ловит дрейф — единственный механизм в репо, у которого есть память.
- **Акк с привязкой к sha256 сумм, а не «флажок».** Флажок-разрешение
  превращается в всегда-открытую дверь. Акка легальна ровно для одного
  прошлого состояния: новый дрейф — новый акк с новым тикетом.
- **Коды отказа разнесены.** «Что-то не сходится» — это враньё через
  недосказанность; оператор обязан знать: сломан текущий набор (3),
  прошлое издание (4/5) или состав (6).
- **Гейт до аттестации.** Аттестовать непроверенный набор — ставить
  подпись под непрочитанным. Порядок: собрал → сверил себя → сверил
  с прошлым → аттестовал → выложил → издал.
- **Санация GHCR вместо ослабления гейта.** Квотная рана лечится
  удалением мусора в пуле хранения (среда), а не `continue-on-error`
  на релизном артефакте: релиз без выложенного точного набора — не релиз.
- **stdlib-only.** Инструмент в TCB не тянет зависимости (урок
  ADR-0015): SBOM-инструмент, требующий SBOM, — рекурсия доверия.
