# ADR-0013: Принятие SINGULARIS — онтологического контура 2.0

Статус: принято · Дата: 2026-10-29 · Субъект: N (мандат) + nous-genesis

## Контекст

Внешний разбор репо (фидбек N, 2026-10-29) показал: организм плотный, но три органа
отсутствуют как **исполняемые** — (1) runtime субъектов: контракты в `.claude/agents/`
есть, тикеты есть, ветка исполнения есть, а механизма «контракт → тикет → run → evidence →
отчёт» нет; (2) self-perception: state/ и снимки есть, единой команды «покажи живое
состояние» нет; (3) closed loop: скан находит GAP, но не порождает тикеты. Дополнительно:
provenance артефактов собирается вручную, эволюция конституции не имеет механизма.

В ответ порождён прототип SINGULARIS (`nous-singularis-prototype.zip`, 2026-10-29) —
синтез мировых практик 2025–2026 (иерархическая оркестрация, evidence-before-effect /
provenance graphs, scaffold self-improvement вместо слепого RSI, state hashing + hard
budgets, verification subagent, bounded autonomy, HITL на high-stakes) на ДНК НОУС.
Прототип существовал как ZIP **вне репо** — это нарушение аксиомы 5 (SSOT): истина
должна жить в организме, а не приложением к нему. Директива N: «интегрируй лучшее из
того, что я тебе даю».

## Решение

1. Комплект прототипа влит в организм как органы (все — в nav, покрыты иммунитетом):
   - `docs/singularis/` — манифест, видение (4 слоя), аксиомы 2.0, архитектура, L0–L4;
   - `docs/spec/singularis/` — ТЗ, runtime-спека, evidence-протокол, схема контракта;
   - `schemas/` — машиночитаемые JSON-схемы (subject-contract, evidence-entry, task-ticket);
   - `docs/spec/roadmap-singularis.md` — 5 фаз 2026-Q4 → 2027-Q2.
2. Очередь воли: тикеты **0010** (runtime MVP) … **0015** (provenance) под Фазу 1–4.
3. Статус утверждений: онтология и спеки — **план/гипотеза** до исполнения (честная
   маркировка по README); A1–A6 переформулированы операционально; **A7/A8 — кандидаты**
   до закрытия 0010 (принятие — L3: ADR + Human).
4. Иммунитет расширен: `tests/test_singularis.py` + органы в REQUIRED_FILES
   (`tests/test_structure.py`) — организм не может «потерять» новые органы незаметно.

## ПОЧЕМУ ТОЛЬКО ТАК, а не по-другому

- **Не писать runtime сразу, без онтологии**: приёмки Фазы 0 дают субъектам исполняемый
  контракт (схемы) раньше кода — обратный порядок рождает runtime под прихоть исполнителя.
- **Не мержить прототип как есть (ZIP → репо без адаптации)**: прототип ссылался на
  «ADR-0011» как на планируемый журнал — в репо он уже реализован (`src/lib/ledger.sh`);
  при интеграции спека опёрла на факт, а не на гипотезу (карта = территория).
- **Не сдвигать существующие тикеты ради номеров из прототипа**: очередь воли непрерывна
  (тест-гейт), номера 0006–0009 заняты живой работой → сдвиг в 0010–0015 зафиксирован
  здесь и в дорожной карте — генеалогия важнее красивых номеров.
- **Не объявлять A7/A8 принятыми**: аксиома, которую не enforce'ит ни runtime, ни тест,
  — декларация; кандидатный статус честнее и согласован с README («либо исполняется,
  либо помечено как гипотеза»).

## Последствия

+ Пробелы фидбека N закрыты на уровне спек/схем/тикетов; каждый следующий коммит runtime
  имеет адрес (0010–0015) и критерий приёмки.
+ Схемы валидируются CI уже сейчас — контракты субъектов становятся enforceable поэтапно
  без big-bang.
− Документы SINGULARIS — гипотезы до Фазы 1: README не обещает работающий `nous run`.
− Дублирование терминологии (аксиомы в двух местах) — до принятия A7/A8; снято будет
  при L3-голосовании по 0010.
