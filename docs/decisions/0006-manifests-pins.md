# ADR-0006: manifests — единая калибровка внешнего мира

Статус: принято · Дата: 2026-10-29 · Решает: владелец

## Контекст

Конвейер зависит от внешних ресурсов: образы, скрипты, actions, версии
инструментов. Если пины рассыпаны по коду (хардкод в скриптах), ревизия
«что и когда мы проверяли» требует чтения всего кода.

## Решение

Два канонических файла: `manifests/pins.yaml` (все внешние зависимости:
источник, версия/SHA, метод проверки, дата) и `manifests/safe-defaults.yaml`
(опасные дефолты). Код читает пины, не содержит их; изменение пина — diff
одного файла; обновление сопровождается датой и методом проверки.

## ПОЧЕМУ ТОЛЬКО ТАК

- Ревизия за конечное время: один файл = одна таблица состояния мира.
- Diff-ревью: обновление пина видно как изменение данных, не кода; дата и
  метод — обязательные поля, делающие «обновление на глаз» невозможным.
- Кросс-модульность: win/linux-ветки потребляют одни и те же пины — рассинхрон
  версий между ветками исключён структурно.

## ПО ДРУГОМУ НЕТ

- Пины рядом с кодом: каждая ревизия — межмодульный grep; забытые пины
  становятся стелс-дрейфом.
- База данных/внешний реестр: лишняя инфраструктура; git diff — уже
  идеальный журнал калибровки с авторством и датой.
- «Latest»-ссылки: невоспроизводимость; сборка от вчера не повторима.

## Последствия

- Тесты проверяют: схему manifests, непустые SHA, даты, устаревание >90 дней.
- Процедура калибровки описана в спеке 01; скрипт `pin_action.sh` —
  канонический способ резолва SHA для actions.
- Рост числа пинов не меняет структуру: ещё одна запись в YAML.
