# ADR-0001: НОУС как SSOT-монорепо

Статус: принято · Дата: 2026-10-29 · Решает: владелец

## Контекст

Нужно место, где живёт конституция, знание, ТЗ, план и исполнение для одного
проекта-организма. Альтернатива — разнести конституцию и код по разным репозиториям.

## Решение

Единое репо `nous`: конституция + документы + форж + инфраструктура в одном теле.
Внутренняя модульность — каталогами (`src/forge/win`, `src/forge/linux`), а не репами.

## ПОЧЕМУ ТОЛЬКО ТАК

- Один источник истины (аксиома сингулярности): решение и его исполнение в одном
  коммите; PR видит и код, и причину.
- Атомарные кросс-модульные изменения: правка ТЗ + правка кода + правка тестов —
  один PR, одна верификация.
- Мультиагентная диспетчеризация через тикеты работает внутри одного тела
  без межреповых протоколов.

## ПО ДРУГОМУ НЕТ

- Отдельный репо-документация: два источника истины, дрейф неминуем.
- Репо на модуль: потеря атомарности; кросс-модульный PR невозможен в принципе;
  версии модулей синхронизируются вручную — новый класс дефектов.

## Последствия

- Монорепо без инструментов монорепы: при росте — Nx/uv-workspaces (R6+).
- Границы модулей дисциплинируются контрактами субъектов, не техникой.
