# ADR-0004: сторонние actions пинуются по полному SHA

Статус: принято · Дата: 2026-10-29 · Решает: владелец

## Контекст

Тег стороннего action можно переподвинуть задним числом. Прецедент:
CVE-2025-30066 (`tj-actions/changed-files`, март 2025) — вредоносный коммит,
теги переподвинуты, 23 000+ затронутых репо, выгрузка секретов CI.

## Решение

Каждый `uses:` в workflows — полный 40-символьный commit-SHA с комментарием
версии (`# v5.0.0`). Резолв SHA — `scripts/pin_action.sh` (ls-remote с
дереференсом аннотированных тегов). Пины фиксируются в `manifests/pins.yaml`
с датой проверки. Тест `tests/test_workflows.py` реджектит непинованный `uses:`.

## ПОЧЕМУ ТОЛЬКО ТАК

- Переподвинуть SHA невозможно; переподвинуть тег — один curl злоумышленника.
  По-другому нет: «pin по короткому тегу» — та же уязвимость другим шрифтом.
- Тест-гейт превращает правило из памятки в инвариант: непинованный use
  = красный CI, а не «кто-нибудь заметит».

## ПО ДРУГОМУ НЕТ

- Теги (`@v5`): комфорт чтения — против подменяемости.
- Полагаться на Dependabot для пинов: он предлагает обновления, но не защищает
  от подмены в момент прогона.
- `actions.lock` уже сейчас: формат требует внедрения через `gh actions-lock`
  и верифицирует owner_id в рантайме — сильнее SHA-пина, но это отдельная
  интеграция; решение отложено сознательно (ADR-0008).

## Последствия

- Обновление action — осознанный акт: резолв нового SHA, обновление пина и
  manifests с датой.
- Коммментарий версии в `uses:` обязателен — иначе diff нечитаем.
