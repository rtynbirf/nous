# ADR-0012: Доктрина секретов и классификация находок

Статус: принято · Дата: 2026-10-29 · Субъект:nous-genesis

## Контекст

Аудит 15 репо аккаунта (2026-10-29) поднял алерт secret-scanning #1 в публичном
`singulyar`: Google API Key в `ИНСТРУМЕНТЫ/RUVSON_Grabber.user.js`. Возник спор из
диалога коллег: «ограничить ключ по referrer/API в Google Cloud Console или отозвать?
СЛОМАЕТ?». Доказательная цепь НОУСа (`docs/genesis/sintez-public-repo-synthesis.md` §5)
установила: это публичная константа клиента YouTube WEB (`INNERTUBE_API_KEY`, живая
страница YouTube содержит её в ytcfg, GitHub code search — 894 публичных файла).
Спор разрешился не выбором «ограничить или отозвать», а классификацией находки:
применять чужую процедуру было нельзя, потому что чужая процедура предполагает, что
ключ твой. Директива владельца: свой независимый путь.

## Решение — три класса находок

НОУС классифицирует каждую находку секрета и ведёт себя по классу:

| Класс | Определение | Проверка класса (метод) | Действие |
|---|---|---|---|
| **A — личный секрет** | Ключ/токен/пароль, владелец которого — аккаунт или субъект НОУСа | Принадлежность подтверждается консолью владельца, журналом выдачи, или ключ даёт доступ к ресурсам аккаунта | Ротация/отзыв **обязателен**, затем удаление из HEAD и (опционально) чистка истории (bfg/git-filter-repo). Алерт резолвится `revoked` |
| **B — публичная клиентская константа** | Ключ, встроенный в чужой публичный клиент (WEB/Android/iOS), раздаётся самим сервисом миллионам копий | Живая страница/приложение сервиса содержит тот же литерал (curl+grep); счётчик публичных копий (code search) значителен | Отзыв невозможен и не нужен. Литерал выносится из HEAD, если коду он не нужен как резерв мёртвого груза; алерт резолвится `false_positive` с доказательствами в комментарии |
| **C — чужой секрет** | Ключ третьего лица, утёкший в чужое или наше репо | Владелец не мы; доступ к ресурсам не наш | НОУС **не отзывает, не ограничивает, не тестирует** чужой ключ. Фиксация в журнале (класс C, места) → responsible disclosure владельцу → инцидент закрывается решением владельца |

Правила сверх классов:

1. НОУС никогда не встраивает секреты класса A в код, шаблоны, pins и workflow.
   Свои секреты — только ephemeral env на время прогона (прецедент: NOUS_PW_HASH в
   `forge.yml`), никогда — файлы в дереве.
2. Найденный класс A подлежит ротации **до** чистки HEAD (порядок важен: сначала
   обезвредить, потом убирать следы).
3. Ответ на вопрос «СЛОМАЕТ?»: сломать может только отзыв класса A без замены
   потребителя. Порядок НОУСа: (1) потребитель получает ключ из окружения/конфига
   пользователя, (2) старый ключ отзывается, (3) ничего не сломано — потребитель
   никогда не зависел от вшитого литерала.
4. Проверка класса B без первоисточника запрещена: «видел похожий ключ в проекте X» —
   это карта без территории; обязательны живой curl+grep сервиса и счётчик копий.

## Применение к алерту #1 (singulyar, RUVSON_Grabber.user.js)

1. Классификация: **B** (публичная константа клиента YouTube WEB; доказательства —
   живая страница `watch?v=dQw4w9WgXcQ` содержит литерал; code search — 894 файла).
2. Ревизия кода: резервный литерал в `innertubePlayer` выносится — скрипт исполняется
   на youtube.com, где `ytcfg.data.INNERTUBE_API_KEY` присутствует всегда; при его
   отсутствии — честный отказ с сообщением (статус FAILED, не притворная работа).
   `СЛОМАЕТ?` — нет: сценарий использования не меняется, меняется только мёртвый
   резерв.
3. Алерт secret-scanning #1 резолвится `false_positive` с комментарием-доказательством.
4. История git (8 локаций) не чистится: класс B не требует ротации, чистка истории
   публичного репо рвёт ссылки — издержки больше пользы.

## ПОЧЕМУ ТОЛЬКО ТАК / ПО ДРУГОМУ НЕТ

- **Почему классы, а не «всё отзываем».** «Отзывай всё» = действие без территории:
  класс B отозвать невозможно (ключ чужой), класс C отзывать нельзя (чужое имущество,
  урон владельцу). Единая процедура для трёх классов порождает либо ложные алерты
  навсегда, либо вред чужим ресурсам.
- **Почему вынос литерала даже для класса B.** Не ради «секрета» (его нет), а ради
  честности карты: вшитая резервная константа притворяется, что скрипт может работать
  без страницы YouTube — не может. Убираем ложное звено, скрипт отказывает явно
  (лестница статусов: честный FAILED лучше притворного UNKNOWN).
- **Почему алерт false_positive, а не wont_fix.** false_positive — утверждение о
  территория («это не секрет»), подтверждаемое доказательствами; wont_fix — признание
  «секрет есть, лень чинить». Первое — карта, второе — капитуляция.
- **Почему не идём в Google Cloud Console.** Чужой путь: консоль принадлежит
  Google-владельцу ключа; у владельца singulyar там нет ни проекта, ни прав.
  Применение чужой инструкции — подмена карты территории (тот самый дефект коллег
  из диалога: «человек ставит задачу — ИИ выполняет» без проверки применимости).

## Последствия

- Субъекты НОУСа при находке секрета обязаны: классифицировать (метод в журнал),
  действовать по классу, ссылаться на этот ADR в решении.
- `src/scan/scan.sh` фиксирует находки как записи журнала с полем class.
- Свои секреты НОУСа — только ephemeral env; гейты CI это не проверяют автоматически
  (secret-scanning GitHub включён на публичных репо) — осознанный остаток риска.
