# ADR-0005: русский язык документов, ASCII-пути

Статус: принято · Дата: 2026-10-29 · Решает: владелец

## Контекст

Владелец и весь контур постановки задач работают на русском. Инструменты
(CI, mkdocs, скрипты) — интернациональны. Термины вендоров не переводимы без
потери смысла (pre-commit, merge queue…).

## Решение

Содержание документов — русский; имена файлов и каталогов — ASCII-slug
(`docs/decisions/0001-ssot-monorepo.md`); код, команды, YAML-ключи, имена ролей
и тикетов — английский технический язык. Конституция (`AGENTS.md`) — русский.

## ПОЧЕМУ ТОЛЬКО ТАК

- Язык субъекта-владельца — язык карты: размышление «ПОЧЕМУ ТОЛЬКО ТАК»
  естественнее и полнее на родном языке; перевод обедняет аргументацию.
- ASCII-пути: инструменты (mkdocs, shell, CI-логи) не дают сюрпризов на
  юникод-путях; кириллица в путях — известный источник кросс-платформенных
  дефектов (форж кросс-платформенный по определению).
- Двуязычный гибрид «русское содержание / английские идентификаторы» —
  норма индустрии для команд СНГ; по-другому нет: полный английский отрезает
  владельца от смысла, полный русский — инструменты от стабильности.

## ПО ДРУГОМУ НЕТ

- Кириллические имена файлов: красиво, но shell-экранирование, URL-энкодинг
  и CI-артефакты становятся полем для дефектов.
- Полный английский: карта написана не на языке субъекта = медленнее
  проверяется = чаще расходится с территорией.

## Последствия

- Тесты линковки документов учитывают русский текст в URL-якорях
  (mkdocs рендерит их корректно).
- Терминология НОУС («субъект», «карта», «контур») — русский канон,
  английские пары — только в коде/инфре.
