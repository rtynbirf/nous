# ADR-0017: тренд-радар — мир снимается еженедельно и механически

Статус: принято (мандат владельца, чат 2026-11-10; тикет 0024) ·
Дата: 2026-11-10 · Решает: владелец

## Контекст

Мандат владельца: «прежде чем ещё мутить — ещё раз в веб поищи лучшие
мировые тренды практик… сделай и настрой так, как ни у кого нет». Волна-2
уже ответила дайджестом (`docs/genesis/world-trends-digest.md`) и
ρ-Governor (тикет 0021) — но обе разведки были РУЧНЫМИ: сессия агента
открыла браузер, прочитала источники, записала. Между сессиями организм
слеп: мир двигается — дом не видит.

Мировая практика 2025–2026 (волна-3 разведки, веб-поиск 2026-11-10):
AGENTS.md принят 60k+ проектов как открытый стандарт инструкций для
агентов (agents.md; InfoQ, 2025-08); исследование arXiv 2601.20404
фиксирует измеримый эффект AGENTS.md на эффективность агентов;
SLSA v1.2 и OpenSSF Scorecard — стержень supply-chain гигиены
(slsa.dev, scorecard.dev). Ниша, которой нет ни у кого: **репозиторий,
который сам еженедельно снимает показания с первоисточников мира и
фиксирует факт сдвига** — не LLM-агент с веб-поиском (недетерминирован,
галлюцинирует, не может провалиться), а честный механический радар.

## Решение

1. `scripts/trend_radar.py` (stdlib-only) — фиксированный список
   первоисточников (`SOURCES`): slsa-framework/slsa-github-generator
   (релизы — канонический трекер SLSA-инструментария; сам репозиторий
   slsa-framework/slsa релизов «latest» не имеет — живой чек 2026-11-10),
   ossf/scorecard (релизы), agentsmd/agents.md (головной коммит;
   openai/agents.md отдаёт 301 на этот же репозиторий),
   actions/runner (релизы), github.blog/changelog/all.atom (5 свежих
   записей; канонический конечный URL фида). Каждый источник → сырой
   факт (тег/SHA/даты/заголовки). Отказ источника — честный отказ
   с именем источника (A2).
2. Сравнение: sha256 канонического JSON фактов против
   `state/trend-radar.json`. Три режима: `first-run` (база записана,
   треда нет), `stable` (state не перезаписывается — ритм без шума),
   `moved` (state перезаписан, сдвиги перечислены old→new).
3. Сигнал: тред-issue с лейблом `trend-radar` — первый сдвиг открывает
   тред, дальнейшие дописывают комментариями (один катящийся тред,
   без шторма уведомлений — гигиена §3 AGENTS.md). Тело треда — ТОЛЬКО
   сырые факты и явный закон: интерпретация и превращение сигнала в
   работу — через тикет `tasks/README.md`.
4. `.github/workflows/trend-radar.yml` — еженедельно (среда 06:03 UTC,
   смещённый ритм по образцу ПУЛЬС) и по диспатчу; state-файл
   коммитится от `radar-bot` только при реальном сдвиге
   (x-access-token подстановка — паттерн ПУЛЬС v2, persist-credentials:
   false — канон безопасности).
5. `tests/test_trend_radar.py`: fingerprint (порядок ключей не влияет),
   три режима compare, парсер atom на фиксе, дедупликация треда
   (pull_request игнорируется), main-контур v1→v2 на подмене сети.

## ПОЧЕМУ ТОЛЬКО ТАК

- **Механический радар, а не LLM-разведка.** LLM-агент с веб-поиском
  не может быть гейтом: он не проваливается предсказуемо и не даёт
  воспроизводимых показаний (A10). Радар снимает сырые факты — их
  можно перечитать и оспорить.
- **Фиксированный список источников через правку кода.** Источник,
  добавленный тихо, — источник, который никто не заказывал. Расширение
  списка — ADR/тикет, как расширение диапазона датчика.
- **Сдвиг — факт, не суждение.** «Scorecard выкатил v5.2» — факт;
  «надо обновиться» — суждение, и оно живёт в тикете, где его можно
  опровергнуть. Радар не выдаёт рекомендаций — иначе он врал бы
  о причине (A2).
- **Один катящийся тред.** Каждое движение мира — новый issue = шторм
  уведомлений = заглушенный радар. Один тред + комментарии = сигнал
  виден, шум отсутствует.
- **state в репо, а не в кэше раннера.** Кэш раннера исчезает;
  история показаний в git — часть кардиограммы организма: видно, когда
  и что именно сдвинулось.
