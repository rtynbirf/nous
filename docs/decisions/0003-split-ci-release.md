# ADR-0003: release отделён от ci

Статус: принято · Дата: 2026-10-29 · Решает: владелец

## Контекст

Конвейер, где сборка, тесты и публикация живут в одном воркфлоу с общими правами,
— вектор атаки: компрометация одной ветки конвейера даёт всё сразу. Прецеденты:
Shai-Hulud 1.0/2.0 (2025) — саморазмножающийся червь npm, крадущий publishing-токены
и заливающий свои воркфлоу в затронутые репо.

## Решение

Два независимых воркфлоу: `ci.yml` (contents: read; верификация: тесты, секреты,
zizmor, docs) и `release.yml` (запуск только по тегу `v*` или вручную; публикация
артефактов; аттестация за гейтом `ENABLE_ATTESTATION`). Права минимальны на каждом
уровне; checkout с `persist-credentials: false`; пины по полному SHA.

## ПОЧЕМУ ТОЛЬКО ТАК

- Разделение прав: компрометация CI не даёт публиковать; компрометация release
  не даёт править код. По-другому нет: общий воркфлоу = единая точка компрометации.
- Короткие токены: release работает с минимальным набором прав на время прогона,
  а не с постоянными секретами.
- Тег — осознанный акт: публикация не может случиться «случайным push в main».

## ПО ДРУГОМУ НЕТ

- Один воркфлоу «всё-в-одном»: экономия 40 строк YAML против целого класса атак.
- Публикация из локальной машины владельца: нет генеалогии (провенанса) и
  воспроизводимости; артефакт вне CI не привязан к коммиту.

## Последствия

- Аттестация (SLSA Build L2) включается переменной `ENABLE_ATTESTATION=1`:
  на приватном репо требует GitHub Enterprise Cloud; выключена по умолчанию.
- Рост числа артефактов форжа (R3–R5) не расширяет права CI.
