# ADR-0002: AGENTS.md как конституция агентов

Статус: принято · Дата: 2026-10-29 · Решает: владелец

## Контекст

N субъектов-агентов (Claude Code, Codex, Copilot, Cursor, Gemini CLI…) работают
в репо. Каждому нужны команды, правила и границы. Инструкции «в промпте сессии»
умирают вместе с сессией.

## Решение

`AGENTS.md` в корне — плотный (≤8KB) конституционный индекс: карта репо, команды,
железные правила, протокол тикета. Вендор-специфика — в точечных файлах:
`.claude/agents/*` (контракты ролей), `.cursor/rules/*.mdc`, `.github/copilot-instructions.md`.
Глубокие объяснения — в `docs/concepts/` по требованию.

## ПОЧЕМУ ТОЛЬКО ТАК

- AGENTS.md — де-факто стандарт 2026 (60k+ проектов, Linux Foundation): читается
  всеми мажорными агентами без настройки. CLAUDE.md/.cursorrules по отдельности —
  вендор-лок.
- Плотный индекс в AGENTS.md показывает лучшую исполнимость, чем «умная»
  подгрузка skills (эвалы Vercel: 8KB-индекс — 100%, skills — ≤79% и часто
  вообще не вызываются).
- «Меньше—плотно—всегда перед глазами; глубина — по требованию» — инженерия
  контекста 2025–2026.

## ПО ДРУГОМУ НЕТ

- Дублировать конституцию в каждом вендор-файле: дрейф копий.
- Один вендор-файл без AGENTS.md: смена инструмента = перенос правил вручную.
- Гигантский AGENTS.md со всем знанием: контекстный налог на каждую задачу.

## Последствия

- Правило размера: файл правится только с проверкой, что он остался плотным.
- Свежие инструменты, читающие AGENTS.md, работают из коробки; новые контракты
  ролей добавляются в `.claude/agents/` без изменения конституции.
