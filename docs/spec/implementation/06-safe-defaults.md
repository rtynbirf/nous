# 06 — Безопасные дефолты форжа

Субъекты: все · Фаза: сквозная · Канон: `manifests/safe-defaults.yaml`
Понимание принципа: [concepts/safe-defaults.md](../../concepts/safe-defaults.md)

## Инварианты генерируемых конфигураций

| Конфиг | Ключ | Значение по умолчанию | Почему |
|---|---|---|---|
| autounattend.xml | `DiskConfiguration/WillWipeDisk` | `false` | сборщик не стирает носитель хоста |
| autounattend.xml | `UserAccounts` | не генерируются без параметров | учётки — решение владельца |
| preseed.cfg | `d-i partman/confirm_nooverwrite` | `true` | подтверждение перед любой разметкой |
| preseed.cfg | `d-i partman-auto/disk` | подставляется из probe | без probe диск не выбирается |
| обе | источники | только из пинов | непинованный URL — ошибка сборки |

## Гейты согласия (когда опасное всё-таки нужно)

Опасная операция допускается при одновременном выполнении:
1. Дефолт в `manifests/safe-defaults.yaml` не инвертирован кодом — операция
   запускается с явным флагом (`--i-understand-destructive`), который не может
   быть дефолтом скрипта.
2. В тикете есть явное подтверждение владельца (цитата/ссылка на согласие).
3. Probe снят не ранее 10 минут назад (территория свежая).
4. Операция логируется полностью до запуска (план → лог → исполнение).

Отсутствие любого из четырёх = операция не выполняется, тикет возвращается.

## ПОЧЕМУ ТОЛЬКО ТАК

1. **Двойное подтверждение, не одно.** Один гейт обходит один баг; два
   независимых гейта требуют одновременных двух дефектов. По-другому нет:
   инциденты 2024–2026 (xz, tj-actions, Shai-Hulud) — все о пробитии одного звена.
2. **Свежий probe.** Территория устаревает: диск, свободный утром, может быть
   занят вечером. Гейт свежести снимает класс «сборка по устаревшей карте».
3. **Лог до исполнения.** Запись плана перед действием даёт разбор неудач
   без домыслов; лог после — только хронику.

## Тесты-гейты (исполняемая карта принципа)

- Рендер любого конфига с wipe-инверсией → тест красный (обязан быть).
- Скрипты форжа не содержат паттернов деструктива вне явно помеченных
  гейт-функций (grep-тест).
- `manifests/safe-defaults.yaml` не ослаблен: тест сверяет ключи с эталоном.

## Критерии приёмки

1. Тесты-гейты зелёные; негативные сценарии покрыты.
2. Документация инвариантов совпадает с кодом рендера (сверяется тестом).
3. Любое расширение списка дефолтов — через ADR.
