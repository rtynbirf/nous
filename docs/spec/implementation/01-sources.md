# 01 — Источники и пины

Субъект: forge-architect · Фаза: R1 · Тикет: 0001

## Задача модуля

Каждая внешняя зависимость конвейера получает запись в `manifests/pins.yaml`:
URL официального источника, идентификатор версии, SHA256 (для артефактов) или
коммит-SHA (для actions), метод проверки, дата проверки. Форж не обращается
к ресурсам, отсутствующим в пинах.

## Официальные каналы (кандидаты в пины)

| Ресурс | Официальный канал | Что пинуем |
|---|---|---|
| Windows-образ | официальный канал получения образов Microsoft (спека 03) | версия сборки, SHA256 ISO |
| Fido (скрипт получения) | репозиторий `pbatard/Fido` | релиз-тег + SHA256 скрипта |
| Debian netinst (+firmware) | `debian.org` / официальный CDN | версия 12.x, SHA256 ISO |
| Ubuntu Server ISO (опция) | `releases.ubuntu.com` | версия LTS, SHA256 ISO |
| xorriso, DISM/oscdimg | пакетные репозитории дистрибутива / ADK | версия, пакет-источник |
| Actions CI | `actions/*`, `gitleaks`, `pre-commit-hooks` | 40-символьный commit SHA |

## ПОЧЕМУ ТОЛЬКО ТАК

1. **Официальные источники, не зеркала.** Зеркало — дополнительное звено доверия;
   официальный канал уже имеет инфраструктуру контрольных сумм. По-другому нет:
   каждое лишнее звено — поверхность xz-типа.
2. **Пин с датой, не «последняя версия».** «Latest» не воспроизводим: завтра он
   другой, и сборка невоспроизводима. Пин делает сборку повторимой и аудит —
   конечным.
3. **Динамическое получение при фиксированной калибровке.** Требование «актуальные
   дистрибутивы» выполняется обновлением пинов (процедура калибровки), а не
   «качаем что сегодня отдаёт сервер». Актуальность — свойство процесса калибровки,
   не свойства ссылки.

## Формат записи пина

```yaml
windows-image:
  source: "https://<официальный канал>"
  version: "<сборка>"
  sha256: "<hex>"
  verified_at: "2026-10-29"
  method: "скачан → sha256sum сверён → залит в целевую среду"
```

## Процедура калибровки (обновления пинов)

1. Тикет `калибровка` с перечнем кандидатов на обновление.
2. Для каждого: получить официальный SHA256 от источника; скачать; сверить;
   обновить пин с новой датой; прогнать `verify.sh`.
3. Если официальный SHA не совпал — стоп, тикет `security`, пин не обновляется.

## Критерии приёмки

- `manifests/pins.yaml` валиден (тест структуры), ключи не пустые, даты есть.
- `verify.sh` проверяет: формат, непустоту SHA, отсутствие пинов старше 90 дней
  без флага `stale-ok`.
- Каждая запись имеет поле `method` (как именно проверяли).
