# 02 — Probe: обследование хоста

Субъект: forge-architect (спека) → сборщик ветки (реализация) · Фаза: R2 · Тикет: 0002

## Задача модуля

Единая точка входа для обследования среды перед любым действием конвейера.
Выход: `probe.json` (машиночитаемо) + `probe.log` (сырые команды и их вывод).
Модуль строго read-only: ни одной операции записи вне временного каталога.

## Что обследуется

| Домен | Что фиксируем | Зачем |
|---|---|---|
| OS | семейство, версия, разрядность, тип сборки | выбор ветки конвейера |
| Загрузка | BIOS vs UEFI (присутствие `/sys/firmware/efi` на Linux; `bcdedit`/реестр на Windows) | конфигурация гибридного ISO |
| Железо | CPU (ядра/архитектура), RAM, диски (модель, ёмкость, свободно) | оценка ресурсов для сборки |
| Сеть | доступность пиновых источников (HEAD-запрос с таймаутом) | ранняя калибровка отказов |
| Каталог вывода | путь, права, свободное место, существование | безопасный вывод артефактов |
| Инструменты | наличие DISM/oscdimg (win), xorriso, sha256sum (linux) | контроль предварительных требований |

## Формат выхода

```json
{
  "timestamp": "ISO-8601",
  "host": {"os": "...", "arch": "...", "boot": "uefi|bios|unknown"},
  "resources": {"cpu_cores": 0, "ram_gb": 0, "disks": [{"model": "...", "free_gb": 0}]},
  "network": {"<pin-key>": {"reachable": true, "latency_ms": 0}},
  "output_dir": {"path": "...", "free_gb": 0, "writable": true},
  "tools": {"xorriso": "1.5.x", "sha256sum": "coreutils"}
}
```

## ПОЧЕМУ ТОЛЬКО ТАК

1. **Обследование до действия.** Карта территории обязательна до вмешательства:
   без probe конвейер делает предположения о среде — источник неявных дефектов.
2. **JSON + лог, не «человекочитаемый отчёт».** Верификатор и следующие фазы
   потребляют данные; лог сырых команд делает выводы воспроизводимыми.
3. **Read-only по построению.** Probe, способный писать, не отличим от угрозы.
   По-другому нет: обследование с побочными эффектами недопустимо в модуле,
   отвечающем за доверие.

## Реализация и тесты

- `src/forge/probe/probe.py` (или sh-парные скрипты веток) — единый интерфейс:
  `probe run --output <dir>`.
- Тесты на фикстурах: подставные `/sys`-деревья и выводы команд; CI не трогает
  реальное железо.
- Каждое поле JSON имеет тест-фикстуру и валидатор схемы.

## Критерии приёмки

1. `probe run` на чистой CI-машине (ubuntu) завершается кодом 0 с валидным JSON.
2. Все команды probe зафиксированы в логе с сырыми выводами.
3. Тесты: схема JSON, обработка отсутствующих доменов (значение `unknown`, не ошибка).
4. Нет ни одной записи вне temp-каталога (проверяется в тесте).
