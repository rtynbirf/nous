# 04 — Linux-ветка: сборка ISO (равноправная)

Субъект: forge-builder-linux · Фаза: R4 · Тикет: 0004
Предусловия: R1 (пины), R2 (probe). Зависимость от R3: отсутствует сознательно.

## Конвейер ветки

1. **Получение образа.** Официальный netinst Debian 12 (с firmware-вариантом для
   совместимости контроллеров) или Ubuntu LTS (решение фиксируется в пинах);
   SHA256 сверяется с официальным `SHA256SUMS` источника до сборки.
2. **Ответ установки.** `preseed.cfg` рендерится из шаблонов
   `src/forge/linux/templates/`: локаль, клавиатура, разметка — с явным
   `d-i partman/confirm_nooverwrite` и без автоматического стирания (спека 06);
   создание пользователя без пароля по умолчанию не допускается: пароль или
   ключ — только из параметров владельца, не из репо.
3. **Сборка гибрида.** Распаковка initrd/ISO-слоя в temp, вложение preseed,
   xorriso с двойным загрузчиком:

   ```
   xorriso -as mkisofs -r -J -joliet-long -isohybrid-mbr <isolinux/isohdpfx.bin> \
     -c isolinux/boot.cat -b isolinux/isolinux.bin -no-emul-boot \
     -boot-load-size 4 -boot-info-table \
     -eltorito-alt-boot -e boot/grub/efi.img -no-emul-boot \
     -isohybrid-gpt-basdat -o <выход>.iso <каталог-источника>
   ```

4. **Верификация** (R5): SHA256, eltorito-записи BIOS и UEFI, размер.
5. **Вывод:** `NOUS_TARGET_DIR/linux/<дата>/<имя>.iso` + SHA256SUMS + лог.

## ПОЧЕМУ ТОЛЬКО ТАК

1. **Равноправная ветка, не «догоняющая».** Требование ТЗ: «+ЛИНУКС» — вторая
   полноценная линия. Общая только вертикаль (probe/verify/pins), конвейер
   свой. По-другому нет: зависимость от Windows-фазы делает Linux хвостом,
   что нарушает аксиому поливариантности.
2. **xorriso, а не genisoimage.** xorriso — актуальный стандарт Debian,
   поддерживает `-isohybrid-mbr` + GPT-баздату (одновременный BIOS+UEFI);
   genisoimage не поддерживает гибрид UEFI.
3. **Firmware-вариант netinst.** Debian 12 без firmware не поднимает сеть на
   ряде контроллеров → preseed недоступен на первой загрузке. Firmware-вариант
   снимает класс отказов целиком.

## Безопасность

- Все операции — в temp-каталоге; запись на физические носители запрещена
  (`write_to_physical_media=false`).
- Пароли/ключи не входят в репо: preseed рендерится с плейсхолдерами, значения
  подставляются из окружения владельца и не попадают в лог (маскирование).

## Тесты (CI, ubuntu-latest)

- Рендер preseed из фикстур → инвариант «нет автоматического стирания».
- Аргументная строка xorriso: генерация и сверка с эталоном.
- Проверка доступности пинового источника (мок-сервер).
- SHA256-протокол на фикстурном артефакте.

## Критерии приёмки

1. Статические тесты зелёные в CI; реальная сборка — в целевой среде владельца.
2. Артефакт с SHA256, логом, версией пинов.
3. Ветка развивается независимо: тикеты R4 не блокируются фазой R3.
