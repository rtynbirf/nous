# 05 — Верификация артефактов и лог-протокол

Субъект: forge-verifier (принятие) + архитектор (спека) · Фаза: R5 · Тикет: 0005

## Задача модуля

Каждый артефакт форжа получает доказательную карту: что это, откуда, как собран,
чем проверен. Верификация — независимый шаг: артефакт, не прошедший её, не
переносится в `done/` и не считается существующим.

## Чек-лист верификации ISO

1. **SHA256** сходится с расчётным по завершению сборки и записан в SHA256SUMS.
2. **Структура:** наличие `boot/`, корректный eltorito-каталог; для Windows —
   `sources/install.*` и `boot/etfsboot.com`-след в загрузочной записи; для Linux —
   isolinux+grub-записи BIOS и UEFI (проверка утилитой `isoinfo`/`xorriso -indev`).
3. **Конфигурации:** отрендеренный `autounattend.xml`/preseed проходит инварианты
   безопасных дефолтов (wipe=false; нет хардкод-секретов).
4. **Генеалогия:** версия пинов, дата сборки, probe-снимок хоста, коммит репо.
5. **Лог:** полный сырой вывод команд фазы, без секретов (маскирование перед записью).

## Лог-протокол

Единый формат: `logs/<фаза>/<дата>-<модуль>.log`, первая строка — JSON-заголовок
(коммит, пины, probe-снимок), далее — команды с сырыми выводами и кодами возврата.
Правила: маскирование потенциальных секретов до записи; append-only; gitleaks
проверяет каталог логов в CI.

## ПОЧЕМУ ТОЛЬКО ТАК

1. **Верификация отдельным субъектом.** Сборщик проверяет свою работу слабее
   независимого: конфликт интересов встроен в роли. По-другому нет: самоприёмка
   обнуляет карту=территорию.
2. **Сырые выводы, не пересказ.** Пересказ теряет аргументы команд и коды
   возврата — единственные воспроизводимые улики.
3. **Append-only логи.** Редактируемый лог не улика; правило даёт audit-цепочку.

## Инварианты (проверяются тестами)

- Верификация не может быть пропущена: фаза сборки без фазы верификации = красный
  контур (тест на порядок шагов в скриптах).
- Маскирование применяется до записи (тест на фикстуре с фейковым токеном).
- Каждая запись SHA256SUMS имеет артефакт и наоборот (тест на фикстурах).

## Критерии приёмки

1. Фикстурный ISO-стаб проходит чек-лист; подделанный — не проходит (отрицательный тест).
2. `verify.sh` включает верификацию структуры manifests и логов.
3. Вердикты верификатора фиксируются в `tasks/done/` со ссылками на доказательства.
