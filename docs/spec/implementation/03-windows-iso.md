# 03 — Windows-ветка: сборка ISO

Субъект: forge-builder-win · Фаза: R3 · Тикет: 0003
Предусловия: R1 (пины), R2 (probe)

## Конвейер ветки

1. **Получение образа.** Скрипт Fido (пин из `manifests/pins.yaml`, SHA256 сверен)
   запрашивает актуальный релиз из официального канала Microsoft; итоговый ISO
   сверяется с официальной контрольной суммой при доступности канала.
2. **Генерация ответа установки.** Шаблон `autounattend.xml` рендерится из
   `src/forge/win/templates/` с параметрами probe (индекс редакции, локаль,
   разметка диска). Ключевое: `WillWipeDisk=false` по умолчанию (спека 06);
   офлайн-сценарий создаёт локальную учётную запись (политика Microsoft для
   сетевых сценариев OOBE может измениться — параметр фиксируется в пинах).
3. **Сборка ISO.** Модификация образа: файл ответа в корень; при необходимости —
   DISM `/Export-Image` для урезания. Загрузочный образ собирается oscdimg с
   двойной загрузочной записью (BIOS+UEFI):

   ```
   oscdimg -m -o -u2 -udfver102 ^
     -bootdata:2#p0,e,b<path>\etfsboot.com#pEF,e,b<path>\efisys.bin ^
     <каталог-источника> <выход>.iso
   ```

4. **Верификация** (фаза R5): SHA256, наличие загрузочных записей, размеры.
5. **Вывод:** `NOUS_TARGET_DIR/win/<дата>/<имя>.iso` + `SHA256SUMS` + полный лог.

## ПОЧЕМУ ТОЛЬКО ТАК

1. **Fido из pbatard, не хардкод-ссылки.** Ссылки на образы Microsoft
   нестабильны (fwlink-перенаправления меняются); Fido — поддерживаемый
   скрипт, официальный по происхождению, пинуемый по SHA256. По-другому нет:
   хардкод ломается тихо, без даты «когда проверялся».
2. **oscdimg с `-bootdata`, а не утилиты третьих сторон.** Двойная загрузочная
   запись — документированная возможность родной утилиты ADK; сторонние
   обёртки добавляют звено доверия.
3. **wipe=false и в шаблоне, и в верификаторе.** Одна защита — не защита:
   верификатор отдельно проверяет, что отрендеренный XML не содержит
   инвертированного дефолта.

## Безопасность

- Все операции записи — только в `NOUS_TARGET_DIR` и temp-каталог.
- Никаких операций над носителями хоста (см. safe-defaults).
- Лог маскирует потенциальные секреты (gitleaks проверяет и логи).

## Тесты (CI-среда без Windows-хоста)

- Рендер `autounattend.xml` из фикстур probe → XSD-структурная валидация.
- Инвариант wipe=false в отрендеренном XML (тест-гейт).
- Команда oscdimg: генерация аргументной строки, сверка с эталоном.
- SHA256-протокол: фикстурный артефакт → ожидаемая запись в SHA256SUMS.

## Критерии приёмки

1. Статические тесты зелёные в CI; реальная сборка — в целевой среде владельца
   по тикету, с сырыми выводами в отчёте.
2. Артефакт сопровождается SHA256, логом и указанием версии пинов.
3. Любое отклонение от спеки — ADR до кода.
