# ТЗ: НОУС-ФОРЖ (инстанциация НОУС под задачу автоматической сборки ISO)

Версия: 1.0 · Дата: 2026-10-29 · Владелец: rtynbirf · Статус: утверждено к исполнению
Порядок и фазы: [roadmap](roadmap.md) · Исполнение: [диспетчеризация](implementation/07-agent-dispatch.md)

## 1. Цель

Создать самодостаточный модульный конвейер «форж», который по одной команде:
активирует рабочую среду → обследует железо и ОС хоста → получает актуальные
дистрибутивы из официальных источников → собирает загрузочные ISO Windows и Linux
→ проверяет артефакты (SHA256, структура, загрузочные записи) → выдаёт результат
в заданный каталог → пишет полный лог сырых команд.

## 2. Формальные слои (обязательны к исполнению)

1. **Карта→территория.** До каждого действия — обследование (probe) хоста и каталога
   вывода; после — сверка факта с ожиданием. Отчёт только сырыми выводами команд.
2. **ПОЧЕМУ ТОЛЬКО ТАК / ПО ДРУГОМУ НЕТ.** Каждый выбор (источник, инструмент,
   порядок шагов) фиксируется в спеках 01–07 и ADR с явными альтернативами.
3. **Самодостаточность.** Конвейер восстанавливается из репо (`bootstrap`) и не
   требует знаний вне репо; все внешние зависимости — пины из `manifests/pins.yaml`.
4. **+ЛИНУКС — равноправная ветка.** Linux-модуль развивается своим циклом (фаза R4),
   не «догоняет» Windows; у каждой ветки — свой субъект-сборщик и свои тесты.
5. **N=СУБЪЕКТ≠ИНДИВИД.** Исполнители — субъекты по контрактам `.claude/agents/`
   (архитектор, сборщики win/linux, верификатор, хронист); права и запреты — в файлах.

## 3. Границы и безопасность

- Опасные дефолты пассивны: `manifests/safe-defaults.yaml`. Стирание носителей,
  запись на физические USB/CD, публикация — никогда не выполняются автоматически.
  В генерируемых `autounattend.xml`/preseed параметр wipe диска по умолчанию `false`
  и меняется только явным решением владельца (спека 06).
- Все загрузки — из официальных источников с проверкой SHA256 до использования.
- Форж исполняется в целевой среде владельца (Windows-хост для Windows-ветки,
  Linux-хост для Linux-ветки); CI-среда гоняет только статические и структурные тесты.

## 5. Критерии приёмки конвейера (DoD цели)

1. `bootstrap → verify` зелёные на чистой машине обеих веток (win/linux, где применимо).
2. Одна команда запускает фазу целиком; прерывание фазы не оставляет частичных
   артефактов без пометки в логе.
3. Каждый артефакт: SHA256 + путь + лог сырых команд + соответствие спеке.
4. Ноль деструктивных операций без подтверждения; ноль секретов в логах.
5. Изменение любого решения оформлено ADR; дорожная карта отражает фактический статус.

## 6. Известные факты среды (проверены 2026-10, см. manifests)

- Windows 10 достиг конца поддержки 2025-10-14; целевой сегмент — Windows 11 и
  актуальные сборки через официальный канал получения образов.
- Утилита Fido сопровождается репозиторием pbatard/Fido; подписи/SHA пинуются,
  источник перепроверяется при каждом обновлении пина.
- oscdimg допускает двойную загрузочную запись (BIOS+UEFI) через `-bootdata`;
  для Linux-ветки гибрид собирается xorriso.
- Debian 12 требует firmware-пакетов для ряда сетевых/дисковых контроллеров —
  источник netinst выбирается с учётом firmware (спека 04).

## 7. Что ТЗ НЕ содержит (сознательно)

- Конкретных серийных номеров, обходов активации и прочего серого: форж собирает
  дистрибутивы из официальных каналов; лицензирование — зона ответственности владельца.
- Гарантий запуска на всём железе: probe фиксирует среду, спеки задают минимум
  поддерживаемого; расширение минимума — через тикеты и ADR.
