# Верификация инструкции LLM=ИИ — референс

> Данные проверки для [инструкции v2.0.1](../guides/llm-device-operation.md).
> Всё утверждение здесь либо исполнимо (скрипты в
> `assets/llm-device/`), либо помечено как допущение. Правило
> «Карта = территория» применено к внешнему материалу в полном объёме.
> Родственные органы организма: [журнал доказательств
> (ADR-0011)](../decisions/0011-evidence-ledger.md),
> [эмерджентный контур](../concepts/emergence.md).

## 1. Методология

- **Парная контрфактическая абляция (A/C).** Каждый прогон с одинаковым
  начальным состоянием ГСЧ исполняется дважды: A — контур гарантов включён,
  C — контур удалён. Свойство обязано исчезнуть вместе с контуром (критерий
  G-7 канона: «исчезает при удалении управляющего контура»), иначе это не
  контур, а украшение.
- **Разделение обязанностей.** Исполнитель ≠ аудитор: независимые линии ищут
  и цитируют, уровни лестницы присваивает аудитор механической grep-проверкой
  каждой цитаты (проверки двух типов: hit — фраза есть, absence — фразы нет,
  там, где её отсутствие и есть результат).
- **Честная классификация свойств:** ПРОВЕРЕННЫЕ (структурный обход, перебор,
  Монте-Карло) vs ИСТИННЫЕ-ПО-ПОСТРОЕНИЮ (бюджет-монотонность; гаранты в
  симуляции). Смешение этих классов — дефект v1.0, исправленный ревизией.
- **Сид воспроизводимости:** 20260910.

## 2. Структурные свойства FSM (P1–P8) — ALL PASS

FSM: 19 состояний, 25 переходов с гарантами, 4 терминала
(TERM_SOLVED, TERM_SOLVED_CAVEATS, TERM_BUDGET, TERM_ESCALATED).

| Свойство | Вердикт | Детали |
|---|---|---|
| P1 достижимость всех состояний из INIT | PASS | недостижимых нет |
| P2 тупики = только терминалы | PASS | ровно 4 терминала |
| P3 терминалы только из STOP/SYNTH/ESC | PASS | обходных входов нет |
| P4 SYNTHESIS только из STOP_CHECK | PASS | единственный предок |
| P5 каждый цикл-стейт достигает терминала | PASS | все 8 цикловых состояний |
| P6 AUDIT — единственный вход в LEDGER | PASS | preds(LEDGER)={AUDIT} |
| P7 живость | PASS | максимум кратчайшего пути до терминала = 5 шагов (STATE_0) |
| P8 врата журнала | PASS | без узла LEDGER из EXECUTE достижим только T_ESC; честные выходы отрезаны |

## 3. Вето и квадранты

- Вето канона V4.1 — **6 флагов** (не 5): перечисление 2⁶=64, SOLVED
  заблокирован в **63/64**; разрешена единственная комбинация — все шесть
  флагов сброшены.
- Тупиковая пара (STOP_REQUEST ∧ вето) существует и занимает **612 из 1024**
  конфигураций (перебор 2¹⁰ при зависимости no_critical = ¬(F1∨F2∨F6), которая
  в каноне не определена и помечена операторским допущением).
- Квадранты: Q1=13 (честная остановка), Q2=39 (CAVEATS при F4/F5),
  Q2а=612 (форс-CONTINUE, риск зависания), Q3=3 (нормальная работа),
  Q4=357 (работа с флагами).

## 4. Парная абляция — 200 000 пар

| Исход пары | Доля |
|---|---|
| оба чисты | 163 708 (81.85%) |
| A чист ∧ C нарушен (контур необходим) | **36 292 (18.15%)** |
| A нарушен | **0** — на всех прогонах |
| оба нарушены / A нарушен ∧ C чист | 0 |

События в абляции: «карантинная посылка использована» — 31 851 прогон,
«SOLVED при взведённом вето» — 5 605 прогонов. Критерий G-7: **PASS** —
свойства исчезают вместе с контуром. Отозванные числа v1.0 (31/32; «105 485
нарушений») — TOMBSTONE: второе было суммой размеров журнала по посещениям
SPAWN, а ни событием, ни прогоном.

## 5. Живой прогон v2.0 (то, чего симуляция не заменяет)

GOAL: механически проследить каждого гаранта инструкции до текста канона.
Архитектура: 3 независимых исполнителя с чистыми контекстами (линия A —
гаранты цикла, линия B — семантика остановки, линия C — red-team) + аудитор.
Разделение: исполнители не видят выводов друг друга и аудитора; ни одна цитата
не принята на слово — каждая проверена grep-ом. Дефект инструмента аудитора
(окно в 1 строку давало 4 ложных FAIL на растянутых формулах) найден самим
аудитом, исправлен, перепрогон — **33/33 PASS**.

FOLD: ΔI = +14 новых утверждений, −2 инвалидации, +2 resolved unknowns.
DETECT: карантин пуст; противоречия канона внесены в TOMBSTONE (D.1 ↔ ядро
цикла в 3 файлах; инверсия F6 между V4.0:464 и V4.1:473; несчитаемость ΔI из
штатного вывода; утрата блока статусов в V4.1.1). STOP_CHECK: вето F1–F6 = 0.
**Терминал: SOLVED_WITH_CAVEATS** — перечисление в журнале прогона (E8).

## 8. Что НЕ проверено (честная граница карты)

- Независимость исполнителей живого прогона — **контекстная, не модельная**:
  0.95 внутри одного семейства моделей недостижим (канон фиксирует сам);
  несущая проверка — модельно-независимый grep.
- `no_critical_open_item`, `convergence_stability`, окно K, ε (вне V4.1.1) в
  каноне не определены — операторские допущения, ждут следующей редакции канона.
- Механизм MkDocs-строгой сборки репо: прогон на момент интеграции —
  см. PR (сырой вывод приложен там; при недоступности темы — отмечено в PR).
- Поведение реального устройства (не симулятора) на живом GOAL по §1–§4 —
  следующий рубеж: симуляция доказывает спецификацию, устройство доказывает
  только живой прогон.
