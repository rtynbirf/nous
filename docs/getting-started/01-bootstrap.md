# Учебник: от клона до зелёной верификации

Цель: за пять минут пройти полный цикл самодостаточности — клонировать репо,
восстановить среду и убедиться, что карта совпадает с территорией.

## Шаг 1. Клонировать

```bash
git clone https://github.com/rtynbirf/nous.git
cd nous
```

## Шаг 2. Восстановить среду

```bash
bash scripts/bootstrap.sh
```

Скрипт идемпотентен: проверяет `git` и `python3` (минимум 3.11, рекомендуем 3.12), ставит зависимости из
`requirements-dev.txt` (pyyaml, pre-commit, mkdocs-material, zizmor) и активирует
git-хуки pre-commit. Повторный запуск безопасен. Пользователи mise/direnv могут
использовать `.mise.toml` и скопировать `.envrc.example` в `.envrc`.

## Шаг 3. Сверить карту с территорией

```bash
bash scripts/verify.sh
```

Ожидаемый результат: все проверки зелёные. Что выполняется:

1. `python -m unittest` — исполняемая карта: структура файлов, пины workflows,
   целостность ссылок документов.
2. `shellcheck scripts/*.sh` — рефлексы без дефектов.
3. `pre-commit run --all-files` — gitleaks (нет секретов) и гигиена файлов.
4. `zizmor .github/workflows` — аудит воркфлоу.
5. `mkdocs build --strict` — документация собирается без предупреждений.

## Шаг 4. Снять состояние организма

```bash
bash scripts/state.sh
```

В `state/` появится снимок: дата, коммит, счётчики органов. Это эмерджентный слой —
репо измеряет само себя. Снимок коммитится хронистом (`forge-librarian`).

## Шаг 5. Что дальше

- Исполнить задачу: прочитай [ветку исполнения](../guides/execution-branch.md)
  и выбери тикет в `tasks/open/`.
- Понять смысл: [аксиомы](../concepts/axioms.md).
- Добавить субъекта: [новый субъект](../guides/new-subject.md).

Проверь себя: удали виртуальное окружение, повтори шаги 2–3 с нуля — тот же результат.
Это и есть аксиома самодостаточности, исполненная руками.
