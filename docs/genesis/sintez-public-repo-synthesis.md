# Синтез «Public Repo Synthesis» — разбор архива коллег (2026-10-29)

Субъект:nous-genesis. Источник: архив `Public Repo Synthesis.7z` (9 файлов, ~950 KB) —
работа «коллег по цеху ЛЛМ» (GPT-6 в роли «полимата-мультиагента») плюс каталоги
инструментов. Директива владельца: разобрать всё и вся и реализовать у нас, при этом
это **не инструкция к применению** — у НОУС свой независимый путь. Ниже: что в архиве,
что мы берём, что отвергаем и почему только так.

## 2. Прямая связь с НОУСом (ПОЧЕМУ РАЗБОР НЕ ПУСТОЙ)

Находка НОУСа 2026-10-29 (`docs/genesis/audit-2026-10-29.md`): Google API Key в
публичном `singulyar` (алерт secret-scanning #1, `ИНСТРУМЕНТЫ/RUVSON_Grabber.user.js`).
Спор «ограничить по referrer в Google Cloud Console или отозвать? не сломает ли?» —
это ровно та зона, где у коллег есть готовый аппарат: статусы доказательности,
журнал с цепочкой хешей, антигаллюцинационные ворота. Разбор архива закрыл и этот спор —
доказательным фактом, см. §5 и ADR-0012.

## 3. Честный вердикт об архиве коллег

Что у коллег **сделано хорошо** (подтверждено чтением кода, не по описанию):

- Журнал доказательств `ledger.py`: hash chain (seq, prev, sha256 канонического JSON),
  `verify()` ловит правку и удаление строки. Ядро простое и честное.
- Статусная лестница `GAP < UNKNOWN < PARTIAL < CONFIRMED` и правило «планировщик сам
  никогда не ставит CONFIRMED» — операционализация «карта ≠ территория».
- Анонимный клон в чистой среде (`anon_git_env`: HOME подменён, credential helper
  пуст, GIT_SSH_COMMAND=false, токены из env вырезаны) — реальный скан 19/19.
- Исправления v0.1 честно перечислены с методами проверки (16 дефектов, incl. признание
  «заявлено 100 записей — реально 37/71» — количественная галлюцинация поймана).

Что **слабо** (и почему у нас иначе):

- Синдром документо-центризма: в v0.1 документов больше, чем кода; в v0.2 код живой,
  но синтез — план, не сборка («СЛОМАЕТ?»-граница честно признана, но идеал остался недостижен).
- Каталог 2444 инструмента — плоский лексикон без capability-графа, версий, статусов
  жизни и политик (сам ESUT v3 подходил к этому через C1–C8, но ИТОГ-каталог откатился).
- Антигаллюцинационная проверка только статическая и одноразовая (PyPI-сверка при сборке),
  пере-верификации и живого контура здоровья записей нет.
- Про секреты и ключи — только инструменты (gitleaks/trufflehog в списке), доктрины нет:
  ни классификации находок, ни процедуры решения, ни разборки «публичная константа vs
  личный секрет».

## 4. Что НОУС берёт (свой путь реализации)

| Идея коллег | Реализация НОУСа | Отличие (ПОЧЕМУ ТОЛЬКО ТАК) |
|---|---|---|
| Журнал доказательств с hash chain | `src/lib/ledger.sh` + ADR-0011: append-only `state/evidence.jsonl` у каждого прогона | Bash без зависимостей (аксиома 3 — самодостаточность), формат совместим с коллегами, но биндинг к НОУС-фазам (probe/forge/scan) |
| Статусная лестница GAP<UNKNOWN<PARTIAL<CONFIRMED | Та же лестница в `src/scan/scan.sh` + доктрина ADR-0012 | Правило НОУС жёстче: CONFIRMED только от первоисточника (TOFU/живая проверка), PARTIAL — только с методом |
| Анонимный скан публичных репо | `src/scan/scan.sh`: allowlist хостов, чистая среда git, инвентарь, mentions, журнал | Наша цель — калибровка деталей форжа и проверка существования, не «мастерская сборки программ» |
| Capability-модель ESUT (C1–C8) | `docs/reference/tools-catalog.md`: каталог инструментов самого НОУСа по ролям с статусами | Не 2444 позиции-лексикон, а 20+ инструментов, которые НОУС реально использует; каждый со статусом и методом верификации |
| Антигаллюцинационные ворота (CLAIM→METHOD→RAW→LOG→REPEAT) | Уже были в конституции (аксиома 2); теперь с механическим журналом | Журнал — это гейт: без записи прогона утверждение остаётся UNKNOWN |
| Принцип «индивид ≠ человек» | Аксиома 4 НОУС (N=СУБЪЕКТ≠ИНДИВИД) уже в конституции | Коллеги перевели принцип в R1–R6 — мы сверили: совместимо, ничего менять не надо |

Что НОУС **отвергает** и почему:

- Мастерская-синтезатор программ как цель. НОУС — репо-организм с одной миссией
  (форж ISO-носителей); скан — его сенсор, не продукт. Расширение миссии = размытие
  границ субъекта (аксиома 5 — генеалогия решений, не все сразу).
- Публикация каталога по `/.well-known/ai-catalog.json` (ARD). У НОУС нет публичного
  домена-хоста; экспорт через `llms.txt`/`AGENTS.md` уже покрывает потребителей.
- MCP-сервер в ядре. Контур НОУСа исполняется субъектами через ветки и тикеты;
  MCP-надстройка без реального потребителя — карго-культ интерфейсов.
- Хеш-цепочка как «защита от злонамеренника». Коллеги сами пишут: от переписывания
  всего файла не защищает; у нас честнее — журнал живёт рядом с git-историей
  (внешний якорь — сами коммиты), подпись осознанно отложена.

## 5. Разбор спора про ключ (главный практический выход)

Вопрос из диалога: «Ограничьте ключ по referrer/API в Google Cloud Console или
отзови? СЛОМАЕТ?». Доказательная цепь НОУСа (метод зафиксирован в журнале 2026-10-29):

1. `RUVSON_Grabber.user.js:233` — ключ `AIzaSyAO_FJ2SlqU8Q4STEHLGCilw_Y9_11qcW8` —
   резервная константа функции `innertubePlayer`, рядом честный комментарий
   «ключ и версия — публичные константы клиента WEB».
2. Первоисточник №1: живая страница `https://www.youtube.com/watch?v=dQw4w9WgXcQ`
   содержит этот же ключ (поле `INNERTUBE_API_KEY` в ytcfg) — метод curl+grep, счётчик=1.
3. Первоисточник №2: GitHub code search по строке — 894 публичных файла.
4. Вывод: это **публичная константа клиента YouTube WEB**, принадлежит Google, а не
   владельцу аккаунта. Ограничение по referrer и отзыв невозможны (нет доступа к
   чужому Google Cloud проекту), «СЛОМАЕТ?» — сломало бы весь WEB-клиент YouTube,
   чего Google не сделает. Алерт secret-scanning — срабатывание на публичную константу.

Свой путь (без чужой консоли): классификация находки по доктрине ADR-0012 (класс B —
публичная клиентская константа) → вынос литерала из HEAD (скрипту резерв не нужен:
скрипт исполняется на youtube.com, где ytcfg всегда есть; а при его отсутствии —
честный отказ вместо притворной работы) → резолв алерта как false_positive
с доказательствами. Полная процедура — `docs/decisions/0012-secrets-doctrine.md`.
