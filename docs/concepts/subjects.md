# N=СУБЪЕКТ≠ИНДИВИД

Формула мультиагентности НОУС. N агентов работают в одном репо; каждый — субъект
с полным описанием поведения в файле-контракте, а не индивид с неявными прихотями.

## Анатомия субъекта

Контракт `.claude/agents/<роль>.md` содержит пять секций:

1. **Назначение** — зачем субъект существует, какую зону обслуживает.
2. **Права (tools)** — минимально необходимый набор инструментов и путей записи.
3. **Граница (жёстко)** — запреты, сильные прав: конфликт разрешается в пользу запрета.
4. **Протокол отчёта** — какие доказательства обязательны (сырые выводы, SHA256,
   ссылка на тикет).
5. **Запреты** — операции, недоступные никогда (деструктив, публикация, секреты).

## Право против границы

Право отвечает на вопрос «чем работаем», граница — «чего никогда не делаем».
У `forge-builder-win` есть право Bash, но граница запрещает любые операции над
носителями хоста. Это различие — ядро безопасной автономии: агент активен внутри
зоны и инертен на её границе.

## Почему субъект, а не индивид

Индивид действует по внутренней мотивации, субъект — по контракту и тикету.
Практика показывает: у агентов с ограниченным скоупом качество вклада выше
(dotnet/runtime: 67.9% merged для агентов при жёстких тикетах и CI-воротах);
инцидент xz-utils — образец «индивида», накопившего доверие вне контракта.
Контракт делает доверие аудируемым: расхождение поведения с файлом видно в diff.

## Рост и ротация субъектов

- Новый субъект — через [руководство](../guides/new-subject.md): минимальные права,
  явная граница, PR с верификацией.
- Расширение прав существующего субъекта — ADR, а не молчаливая правка.
- Отзыв доверия: контракт правится, субъект лишается зоны; история изменений —
  в git-генеалогии.

## Почему только так

Права в конфиге проверяются (diff, ревью, тесты на структуру); права «в голове»
не проверяются нигде. **По-другому нет:** мультиагентность без контрактов деградирует
в хаос пересекающихся самодеятельностей; с контрактами — в управляемый организм.
