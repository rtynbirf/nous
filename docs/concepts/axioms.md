# Шесть аксиом НОУС

Аксиома — не девиз, а ограничение проектирования: любое архитектурное решение в этом
репо обязано не противоречить всем шести. Нарушение аксиомы — дефект первого порядка
и повод для возврата PR независимо от качества кода.

## 1. РЕПО = ОРГАНИЗМ

Файлы — геном; поведение — не в файлах, а в контуре их взаимодействия. Признак жизни:
репо реагирует на изменение среды (обновление зависимостей, дрейф пинов, новые тикеты)
без ручного вмешательства. Следствие: мёртвый код и неактуальные документы не
«подчищаются декоративно», а либо исполняются, либо удаляются — в организме нет
лишних органов.

**Почему только так.** Архив деградирует: статистика link rot и заброшенных реп
показывает, что без контура самокоррекции любое состояние фиксируется как устаревшее.
**По-другому нет.** Организм без контура = архив; контур без организма = набор
скриптов, которые некому исполнять.

## 2. КАРТА = ТЕРРИТОРИЯ

Каждое утверждение репо принадлежит одному из трёх классов: исполнимое (код, тест,
команда), сгенерированное из исполнимого (state/, SHA256SUMS, llms.txt), либо
явно помеченная гипотеза. Запрещена проза, притворяющаяся фактом.

**Почему только так.** Единственный источник катастроф — несовпадение карты
с территорией (урок xz-utils: payload жил в тарболле, которого не было в git).
**По-другому нет.** Ручная сверка не масштабируется; CI сверяет принудительно.

## 3. САМОДОСТАТОЧНОСТЬ

`clone → bash scripts/bootstrap.sh → bash scripts/verify.sh` — и организация
восстановлена на любой машине. Симметрично: артефакты восстанавливаются из репо
(сборка в CI), а не «где-то лежали».

**Почему только так.** Знание, живущее в головах или на машинах, не версионируется
и умирает вместе с носителем. **По-другому нет.** Любая недостающая инструкция —
это уже дыра в карте.

## 4. N=СУБЪЕКТ≠ИНДИВИД

Каждый агент — субъект: с контрактом (роль, права, границы, протокол отчёта),
правами в конфиге, а не в надежде на «вежливость». Субъектов может быть N; ни один
не является индивидом — то есть не имеет прихотей вне контракта.

**Почему только так.** Практика dotnet/runtime: ограниченный скоуп задач даёт
измеримо высокий merge-rate агентов; безграничный «индивид» порождает самодеятельность
(урок xz: Jia Tan — индивид, накопивший доверие вне контракта). **По-другому нет.**
Доверие без контракта не аудируется.

## 5. СИНГУЛЯРНОСТЬ

Один источник истины на каждый факт. Всё производное имеет проверяемую генеалогию:
пин → источник и дата; артефакт → SHA256 и workflow-прогон; решение → ADR.

**Почему только так.** Два источника истины = гарантированный конфликт версий.
**По-другому нет.** Генезис без записи невозможно подтвердить или опровергнуть.

## 6. ЭМЕРДЖЕНТНОСТЬ

Репо спроектировано так, чтобы порождать поведение, которого нет ни в одном файле:
контур тикетов, верификации, памяти и эволюции. Слой `state/` — самоизмерение
организма; очередь `tasks/` — воля, распределённая между субъектами.

**Почему только так.** Ценность репо выше суммы файлов — иначе это текстовый дамп.
**По-другому нет.** Контур, собранный постфактум поверх готового репо, не приживается:
правила должны существовать с первого коммита.

## Как применять

Решая любую задачу: перечисли аксиомы, найди конфликт, оформи выбор как ADR
с «ПОЧЕМУ ТОЛЬКО ТАК / ПО ДРУГОМУ НЕТ». Если конфликт не разрешается — решение
принимает владелец, а не субъект.
