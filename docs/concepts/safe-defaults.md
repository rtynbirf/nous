# Безопасные дефолты

Принцип: **опасное действие никогда не является дефолтом**. Каждый деструктивный шаг
требует двух независимых подтверждений: пассивного дефолта в конфиге и явного
согласия владельца в тикете. Канонический источник — `manifests/safe-defaults.yaml`;
этот документ объясняет, почему список именно такой.

## Канонический список

| Дефолт | Значение | Опасность при инверсии |
|---|---|---|
| `wipe_disk` | `false` | сборщик ISO сотрёт носитель хоста |
| `write_to_physical_media` | `false` | заливка на реальные USB/CD без контроля |
| `auto_publish` | `false` | артефакты уходят вовне без ревью |
| `repo_visibility` | `private` | приватные планы становятся публичными |
| `push_force` | `false` | уничтожение истории — карты решений |
| `destructive_ops` | `require-explicit-approval` | «маленький» rm разворачивается в катастрофу |
| `secrets_in_repo` | `forbidden` | кража токенов (урок Shai-Hulud) |
| `actions_pinning` | `sha-required` | подмена действия тегом (урок tj-actions) |

## Почему дефолт пассивен, а не активен

Активный дефолт удобен, пока не совпали три независимых дефекта: баг кода, ошибка
в окружении и неверное предположение субъекта. Пассивный дефолт делает совпадение
бессильным: без явного согласия ничего не происходит. Цена — один лишний флаг
в команде; выигрыш — необратимые операции невозможны молча.

Историческая мотивация: в спецификациях форжа, где генерируются `autounattend.xml`
и `preseed`, параметр автоматического разбиения диска (`WillWipeDisk`) по умолчанию
устанавливается в `false` — и меняется только вручную, осознанно, с подтверждением.
См. [спеку безопасных дефолтов](../spec/implementation/06-safe-defaults.md).

## Как меняется список

Только через ADR с разделами «ПОЧЕМУ ТОЛЬКО ТАК / ПО ДРУГОМУ НЕТ» и явным
подтверждением владельца. Ослабление дефолта в коде без ADR — блокировка PR
верификатором вне зависимости от прочего качества. Тесты `tests/` следят,
что файл дефолтов существует и его ключи не удалены.

## Почему только так

Дефолт, рассыпанный по коду, не поддаётся ревизии за конечное время; один
канонический файл — поддаётся. **По-другому нет:** безопасность, которую нельзя
проверить одним взглядом, не используется при спешке — то есть именно тогда,
когда нужна.
