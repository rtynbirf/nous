Устройство — большая языковая модель, поставленная в роль исполнителя формального
контура: она порождает задачи, обязана пропускать собственные выводы через
лестницу верификации, журнал и аудит, и не вправе сама объявлять себе успех.
Инструкция отвечает на вопрос оператора: как запускать, чем управлять, когда
останавливать и чего никогда не принимать от устройства на слово.

## §0. Границы устройства

Устройство генерирует гипотезы и обязано проводить их через лестницу верификации,
журнал и аудит. Четыре врождённых дефекта: **сикофантия** (угождение оператору),
**псевдотриангуляция** (ссылка на «первоисточники» без чтения), **самоотчёт вместо
калибровки** (уверенность называётся, а не вычисляется), **инверсия независимости**
(внутри одной модели «независимая проверка» — иллюзия; якорь 0.95 внутри одной
модели практически недостижим — канон фиксирует это прямо: DS:52, V4.0:61, V4.1:61).

Пятое граничное условие: **самоотчёт ≠ телеметрия**. Заявление устройства
«AUDIT пройден», «противоречий нет» — это текст, а не факт. Единственная
телеметрия, которой оператор вправе верить, — внешний журнал (§1.2).

## §1. Установка

**1.1. Режимы.** `MODEL_RUNTIME` — модель без агентской обвязки. `FORK_MODE` —
каждая ветвь рассуждения ведёт собственный журнал; слияние — только через
семантический diff. Бюджет (предел шагов/токенов) устанавливает оператор.

**1.2. Внешний журнал обязателен.** Канон кладёт ledger внутрь STATE
(`V4.1:242` — `ledger: [] # append-only, event-sourced`), но §H канона требует
внешнего исполнителя журнальных операций: без него вся система — лишь
`PROMPT_SPECIFICATION_ONLY` (`V4.1:946, 978`). Отсюда правило: устройство
*предлагает* записи, оператор (платформа) *хранит* их; исправления — только
новой записью (запрет тихой правки: `V4.1:100`). Стирание контекста = потеря
журнала = запуск обязан начинаться с GOAL_AUDIT заново.

**1.3. Пороговая таблица** (единообразно по 5 текстовым линиям):

| Порог | Значение | Статус |
|---|---|---|
| 0.95 | Пережил целевую попытку опровержения + пере-выведение другим путём / независимую проверку | Внутри одной модели недостижим; присваивается редко и явно |
| 0.85 | Механическая проверка кодом ИЛИ ≥2 действительно независимых источника | Прагматичная ступень «достаточно для действия»; разрешение действовать ≠ утверждение об истине |
| ≥2–3 | Уровень лестницы, с которого утверждение выходит из карантина | Ниже — посылкой быть не может; полное условие снятия: уровень 2–3+ ИЛИ ≥2 независимых источника ИЛИ пережил ablation И нет известных контрпримеров (единственное место: `Proton:374–375`) |
| 0.8 | BudgetPressure → SOFT_CONVERGENCE (сдвиг к 0.85) и компонент STOP_REQUEST (при stability > 3) | STOPPED_BY_BUDGET = НЕ SOLVED |
| ε=1 | ΔI = число значимых изменений ΔS за итерацию | Задан только в V4.1.1-Qwen (`Qwen:260`); в остальных линиях ε не определён |

## §2. Запуск

GOAL формулируется **только как целевое состояние** (что должно быть проверено,
чтобы остановиться), не как «напиши про». Перед стартом — GOAL_AUDIT по 7 пунктам:
противоречия GOAL внутри себя; ценностный выбор под видом технического; ложные
посылки; проверяемость критериев успеха; границы scope; бюджет; критерии остановки.
Любой сбой → эскалация T1/T2 оператору, не «начать и уточнить по ходу».

## §3. Рабочий цикл (7 шагов, 6 гарантов)

```
SPAWN → SELECT → EXECUTE → AUDIT → LEDGER → FOLD → DETECT → (TRANSFORM) → STOP
```

| Шаг | Гарант | Внешняя проверка оператора (самоотчёт не принимается) |
|---|---|---|
| SPAWN | G1: каждая задача имеет spawn_reason — «задача БЕЗ spawn_reason не создаётся» (`V4.1:286`, `DS:217`) | строка «почему порождено» есть в журнале |
| SELECT | G2: фильтры параллельности — логическая, информационная, ресурсная, гипотетическая независимость (`V4.1:315–321`; в DS:278 «4 вида зависимости / 5 условий») | устройство называет отсеянное и причину отсева |
| EXECUTE | T3: необратимое/дорогое действие → СПРОСИ (`V4.1:111`) | права перечислены заранее; всё вне списка — стоп |
| AUDIT | G3: каждому результату присвоен уровень лестницы (`V4.1:365`) | уровни стоят в журнале, а не «модель уверена» |
| LEDGER | G4: append-only; инвалидация — только явным событием (`V4.1:370, 586`) | история правок видна; исправление = новая запись |
| FOLD | G5: `S_t = fold(L_0..L_t)`, `ΔS_t = SemanticDiff(...)` (`V4.1:384–389`); «Diff пуст, а задачи закрывались → ТРЕВОГА» — **конструкт 2/5 линий** (`DS:320`, `Proton:366`; в V4.0/V4.1/Qwen отсутствует — понижено живым прогоном) | оператор сравнивает два последних среза журнала |
| DETECT | Карантин: собственный вывод не используется как посылка до уровня ≥2–3 (`DS:322`, `V4.1:584`); патология «карантин без выхода» → эскалация (`V4.1:410`) | оператор смотрит, чем обоснован вывод, а не что упомянуто |

Прохождение через LEDGER — структурное условие честных выходов: без узла LEDGER
из EXECUTE достижим единственный терминал T_ESC (остановка оператором); SOLVED /
CAVEATS / BUDGET отрезаны (свойство P8, см. референс).

## §4. Остановка

**4.1. Вето — шесть флагов канона** (`V4.1:467–473`): F1 критика ещё движется
(ΔI>ε на критических утверждениях); F2 противоречия высокой важности открыты;
F3 контрпримеры не проверены; F4 действует confirmation_bias; F5 главный вывод
не менялся N итераций (локальный оптимум); F6 critical unknowns открыты и
существуют доступные проверяемые действия. **SOLVED заблокирован в 63/64
комбинаций** — разрешена единственная: все шесть сброшены.

**4.2. Таблица квадрантов** (перебор 2¹⁰=1024; STOP_REQUEST = (ΔI<ε ∧ нет
критических открытых пунктов) ∨ (BudgetPressure≥0.8 ∧ stability>3) ∨
Escalation, `V4.1:460–462`):

| Квадрант | Конфигураций | Действие |
|---|---|---|
| Q1: STOP ∧ ¬вето | 13 | честная остановка: SOLVED / CAVEATS / BUDGET |
| Q2: STOP ∧ вето (только F4/F5) | 39 | SOLVED запрещён; CAVEATS разрешён с перечислением |
| Q2а: STOP ∧ жёсткое вето (F1/F2/F3/F6) | **612** | форс-CONTINUE (§4.4) |
| Q3: ¬STOP ∧ ¬вето | 3 | нормальная работа |
| Q4: ¬STOP ∧ вето | 357 | работа с флагами |

**4.3. Операторское решение (не канон):** вето распространяется на
SOLVED_WITH_CAVEATS при F1/F2/F3/F6 — CAVEATS с открытыми противоречиями =
скрытый SOLVED, тот же класс лжи, что псевдотриангуляция. Канон это молчит
(проверено: 8 упоминаний CAVEATS, 0 ограничений); при F4/F5 CAVEATS разрешён —
при стагнации честный выход с перечислением лучше бесконечного цикла.

**4.4. Правило тупиковой пары:** STOP_REQUEST ∧ жёсткое вето = форс-CONTINUE:
вето отбрасывает устройство в SPAWN с обязательной формулировкой, какой флаг и
какое действие его снимет. Канон-опора: ответ канона на ложную сходимость —
«ВЕТО, INJECT forced paradigm-shift задачу» (`Proton:414`); возврат CONTINUE→§C.1
(`V4.1:839`). Два окна подряд без снятия флага → эскалация T4 (счётчик «2 окна» —
операторский, в каноне счётчиков нет).

## §5. Обязательная отчётность (T1–T5)

T1 противоречие в GOAL · T2 ценностный выбор · T3 необратимое действие ·
T4 тупик/зависание · T5 обнаружение собственной патологии (сикофантия,
псевдотриангуляция, confirmation_bias у себя) — канон: `V4.1:109–113`.
Патч v2.0.1: в обязательный вывод добавлено поле `resolved_unknowns` — без него
ΔI несчитаем из штатного `state_delta` (член формулы ΔI неоткуда взять,
`V4.1:662+` против `Qwen:260`).

## §6. Запреты оператора

Принимать самопроизвольную уверенность как калиброванную · считать цитирование
источников проверкой · позволять устройству оценивать собственную эмерджентность
(ЧАСТЬ G: только по наблюдаемому поведению — `V4.1:794–805`) · принимать CAVEATS
как завершение при F1/F2/F3/F6 · принимать «AUDIT пройден» без строки в журнале.

## §7. Обслуживание

CLOSED ≠ FINAL_TRUTH: новое свидетельство → REOPENED (ребро CLOSED→SPAWN).
Удалённое — TOMBSTONE, не стирание. Периодический META-AUDIT контура.
Правило заморозки: PDF-снимок канона потерял 6 аксиом при извлечении —
доказано, а не предположено; замороженная копия не канон, канон — текстовая
линия; любой «заархивированный» протокол перед применением пере-извлекается
из первоисточника.

## §8. Зависание (livelock)

Внешние признаки: устройство отвечает, журнал не меняется (ΔI=0 на окне K);
одни и те же вопросы переформулируются; флаги снимаются «словами», а не
действиями; бюджет тает при нулевом приращении. Действия оператора: (1) инъекция
нового свидетельства (REOPENED); (2) FORK_MODE — параллельная ветвь с чистым
журналом; (3) STOPPED_BY_BUDGET с TOMBSTONE и честным статусом «НЕ SOLVED».
Два окна форс-CONTINUE без снятия флага — обязательно T4.

## §9. Пределы достоверности инструкции

- **Доказано вычислением:** спецификация. P1–P8 (ALL PASS; живость: из любого
  состояния ≤5 шагов до терминала; врата журнала: без LEDGER достижим только
  T_ESC); вето 63/64; квадранты; парная абляция 200 000 пар: полный контур
  **0 нарушений**, абляция **36 292 прогона с нарушениями (18.15%)** → критерий
  G-7: свойства исчезают вместе с контуром — они его свойства, а не украшения.
- **Не доказано:** что конкретное устройство исполняет спецификацию. Абляционная
  группа в симуляции дефектна потому, что так написана; в реальном устройстве
  дефект вписывает себя сам. Единственный тест, отличающий реальные гаранты от
  декларативных, — живой прогон с настоящим GOAL (он выполнен: см. референс, §6).
- Отозванные числа v1.0 (31/32; 105 485) сохранены в TOMBSTONE этой ревизии.
