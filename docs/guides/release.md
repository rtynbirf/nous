# Как выпустить релиз

Релизный конвейер отделён от CI (ADR-0003). Что делает `release.yml` при пуше тега `v*`:

1. Собирает документацию (`mkdocs build --strict`) и `llms.txt`.
2. Архивирует сайт: `nous-docs-site.tar.gz`.
3. Считает `SHA256SUMS.txt` — генеалогия артефакта.
4. Загружает артефакты прогона (`nous-release-<тег>`).
5. При переменной репо `ENABLE_ATTESTATION=1` — подписывает провенанс
   (SLSA Build L2, Sigstore). Гейт нужен потому, что аттестация на приватном репо
   требует GitHub Enterprise Cloud; переключение — шаг дорожной карты R6.

## Шаги выпуска

```bash
# 1. Убедись, что main зелёный (ci на последнем коммите).
# 2. Тег из main:
git checkout main && git pull
git tag -a v0.1.1 -m "release: docs-срез 0.1.1"
git push origin v0.1.1
```

## Проверка после выпуска

1. Actions → `release` → прогон по тегу — зелёный.
2. Артефакты: `nous-release-<тег>` содержит tar.gz и SHA256SUMS.
3. Локально: скачай архив, `sha256sum -c SHA256SUMS.txt` — сходится.

## Чего release не делает (сознательно)

- Не публикует в реестры и на внешние площадки.
- Не поднимает версию в файлах: SemVer ведёт release-please (roadmap R6).
- Не подписывает бинарные артефакты форжа: их ещё нет (R3–R5); когда появятся,
  порядок тот же: сборка в CI → checksums → аттестация.
