# Как исполнять задачи в ветке `agents/execution`

Ветка `agents/execution` — земля исполнения: здесь агенты работают, здесь
появляются артефакты. `main` — конституция: в него попадает только то, что прошло
верификацию. Решение об этой ветке — [ADR-0007](../decisions/0007-agents-branch-dispatch.md).

## Жизненный цикл тикета

1. **Берём тикет** из `tasks/open/` (файл `NNNN-<slug>.md`). Роль-исполнитель указана
   в тикете; нет твоей роли — не берёшь.
2. **Синхронизируемся:** `git checkout agents/execution && git pull`.
3. **Ветка задачи:** `git checkout -b agents/<роль>/<NNNN>-<slug>` от `agents/execution`.
4. **Исполняем** в границах контракта (`.claude/agents/<роль>.md`) и тикета.
5. **Верифицируем:** `bash scripts/verify.sh` — зелёный обязателен.
6. **PR** в `agents/execution` с описанием по шаблону (альтернативы + доказательства).
7. **Вердикт верификатора** (`forge-verifier`): принят → PR вливается, тикет переносится
   в `tasks/done/` хронистом; возвращён → исправляем по замечаниям.

## Формат тикета

Шаблон — `.github/ISSUE_TEMPLATE/task.md` и файлы в `tasks/open/`. Обязательные поля:
роль, цель (измеримая), границы (пути), критерии приёмки, «ПОЧЕМУ ТОЛЬКО ТАК».

## Правила ветки

- Workflows, manifests, safe-defaults в ветке исполнения не меняются без ADR.
- Прямой push в `agents/execution` запрещён: только через PR (история — карта решений).
- Ветка не защищена технически на этом этапе (приватное репо, roadmap R6); защита —
  дисциплина контрактов и CODEOWNERS.

## Почему так

Тикет ограничивает скоуп — практика dotnet/runtime показала merge-rate агентов 67.9%
именно на ограниченных задачах; изоляция исполнения от конституции сохраняет
инварианты (см. [эмерджентный контур](../concepts/emergence.md)).
