# Как добавить субъекта (агента)

Цель: ввести в организм нового агента с чётким контрактом за один PR.

## Когда нужен новый субъект

Когда существующие роли не покрывают новую зону ответственности: например,
`forge-probe-builder` для модуля детекции железа. Признак необходимости: два и более
тикетов подряд требуют прав, которых нет ни у одной роли.

## Шаги

1. **Имя и назначение.** Имя = `<зона>-<функция>` (kebab-case), например
   `forge-verify-runner`. Одна роль — одна зона ответственности.
2. **Контракт.** Создай `.claude/agents/<имя>.md` с фронтматтером
   (`name`, `description`, `tools`) и телом из пяти разделов:
   **Назначение → Права (tools) → Граница (жёстко) → Протокол отчёта → Запреты**.
   Формат: см. существующие контракты, например `forge-architect.md`.
3. **Права минимальны.** Дай только те tools, без которых роль не работает.
   Запись файлов — только в зону роли. Bash — перечисли, что именно разрешено.
4. **Граница — глаголами запретов.** «Не изменяет …», «Не исполняет …».
   Граница сильнее прав: при конфликте выигрывает запрет.
5. **Интеграция.** Добавь роль в `docs/reference/structure.md` (таблица субъектов),
   при необходимости — в шаблон тикета (`.github/ISSUE_TEMPLATE/task.yml`).
6. **Доказательства.** PR с сырым выводом `bash scripts/verify.sh` и ссылкой на тикет.

## Приёмка

Верификатор проверяет: контракт не расширяет права сверх зоны, тесты `tests/`
зелёные, README/структура упомянуты. Расширение прав существующей роли — это ADR,
не правка молча.

## Почему так

Контракт в файле версионится, ревьюится и наследуется; устная роль — нет.
См. [N=СУБЪЕКТ≠ИНДИВИД](../concepts/subjects.md).
